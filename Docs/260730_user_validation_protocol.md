# TransTaste 사용자 검증 프로토콜

> 작성일: 2026-07-30
> 상태: 실행 준비 완료, 실제 참가자 모집 및 인터뷰는 미실행

## 1. 검증 목적

TransTaste가 단순 번역 도구보다 제한식 해외여행자의 메뉴 결정과 주문에 실질적인 가치를 주는지 확인한다.

검증 질문:

1. 사용자가 설명 없이 첫 스캔을 시작할 수 있는가?
2. 식이 조건을 20초 안에 설정할 수 있는가?
3. 결과 화면에서 30초 안에 먹을 후보와 확인할 후보를 구분할 수 있는가?
4. 점원 표시 화면만으로 주문 항목과 제한 조건을 이해시킬 수 있는가?
5. 무료 대체재 대신 여행 패스 가격을 진지하게 고려하는가?

## 2. 참가자

- 목표 인원: 10명, 가능하면 20명
- 최근 2년 내 해외여행 경험자
- 채식, 비건, 할랄, 알레르기 또는 특정 식재료 회피 경험자
- 제품 개발자·디자이너는 전체 표본의 20% 이하

모집 시 실제 알레르기 반응을 유도하거나 음식을 섭취하게 하지 않는다. 모든 과제는 메뉴 판단과 화면 사용까지만 진행한다.

## 3. 테스트 준비

- 모바일 화면 또는 실제 스마트폰, 세로 390×844에 가까운 크기
- 일본어·태국어·스페인어 메뉴 이미지 각 1개
- 참가자가 직접 가져온 실제 여행 메뉴 1개
- Google Lens 또는 참가자가 평소 쓰는 번역 도구
- `Docs/260730_user_validation_scorecard.csv`
- 테스트 시작 전 브라우저 사이트 데이터 초기화

Supabase, Stripe, 실제 결제는 사용하지 않는다. AI API가 설정되지 않은 세션은 샘플 메뉴 과제에만 사용하고 실제 메뉴 품질 평가에서 제외한다.

## 4. 진행 순서

### 도입 — 2분

진행 문구:

> 해외 식당에서 메뉴를 보고 무엇을 먹을지 결정하는 상황입니다. 화면을 보며 떠오르는 생각을 말해 주세요. 기능을 맞히는 시험이 아니라 제품을 평가하는 시간입니다.

사전 질문:

- 해외 메뉴에서 가장 불편했던 순간
- 제한식 또는 피하는 재료
- 평소 사용하는 번역·검색 방법

### 과제 1: 첫 스캔 — 최대 1분

설명 없이 홈을 보여주고 메뉴 분석을 시작하게 한다.

기록:

- 시작 성공 여부
- 첫 CTA 클릭 시간
- 샘플과 실제 스캔 중 선택한 경로
- 혼동 발언

통과 기준: 80% 이상이 10초 안에 시작한다.

### 과제 2: 식이 조건 — 최대 30초

본인의 식이 조건과 피하는 재료를 설정하게 한다.

통과 기준:

- 80% 이상이 20초 안에 완료
- 저장과 건너뛰기의 차이를 이해
- 기존 알레르기 설정이 사라진다고 오해하는 참가자 10% 미만

### 과제 3: 메뉴 결정 — 최대 2분

다음 질문에 답하게 한다.

1. 피하는 편이 좋은 메뉴는 무엇인가?
2. 직원에게 확인해야 하는 메뉴는 무엇인가?
3. 지금 주문 후보 하나를 고른다면 무엇인가?
4. 그 판단의 근거는 무엇인가?

통과 기준:

- 위험 상태 판별 정확도 90% 이상
- 80% 이상이 30초 안에 주문 후보 선택
- “명시된 우려 없음”을 안전 보장으로 해석하는 참가자 10% 미만

### 과제 4: 주문과 점원 표시 — 최대 1분

메뉴 하나를 주문에 추가하고 점원에게 보여줄 화면을 열게 한다.

통과 기준:

- 90% 이상이 도움 없이 점원 화면 진입
- 원문 메뉴명과 수량을 식당 직원 역할 참가자가 이해
- 제한 조건 누락 또는 과도한 스크롤 없음

### 과제 5: 가격 의향 — 최대 3분

기능 평가를 먼저 마친 뒤 가격 화면을 보여준다.

질문:

- 7일 $2.99와 30일 $5.99 중 실제로 고려할 옵션
- 결제를 망설이게 하는 가장 큰 이유
- 무료 대체재 대신 사용할 조건
- 가장 가치 있는 기능 하나와 없어도 되는 기능 하나

클릭과 발언을 함께 기록한다. 클릭만으로 지불 의향을 확정하지 않는다.

## 5. 비교 과제

같은 실제 메뉴를 참가자가 평소 쓰는 도구와 TransTaste로 각각 판단하게 한다. 순서 효과를 줄이기 위해 참가자의 절반은 TransTaste를 먼저 사용한다.

측정:

- 주문 후보 결정 시간
- 위험 재료 발견 수
- 추가 검색 또는 질문 횟수
- 확신도 1–5점
- 점원에게 보여줄 준비도 1–5점
- 선호 도구와 이유

## 6. 데이터 처리

앱의 가격 화면에서 `이 브라우저의 검증 데이터 내보내기`를 눌러 JSON을 저장한다.

저장되는 항목:

- 이벤트 이름
- 시각
- 입력 방식, 위험 상태, 선택 요금제 같은 비식별 속성

저장하지 않는 항목:

- 메뉴 이미지와 원문
- 이메일, 이름, 위치
- 결제정보
- 자유 발화와 알레르기 의료정보

인터뷰 메모에는 참가자 ID만 사용하고 연락처와 분리 보관한다.

## 7. 의사결정 기준

### Go

- 첫 스캔 10초 내 시작률 80% 이상
- 결과 후 주문 또는 점원 표시 진입률 40% 이상
- 비교 도구보다 결정 시간이 빠르거나 확신도가 1점 이상 높음
- 가격 관심 클릭 20% 이상이며 인터뷰에서도 실제 결제 조건이 구체적

### Pivot

- 스캔과 결과 사용성은 통과하지만 가격 관심이 10–20%
- 점원 표시 또는 회화 기능만 반복적으로 높은 평가
- 이 경우 무료 분석 + 유료 주문 도우미 포지셔닝을 재검증

### Stop

- 첫 스캔 시작률 50% 미만
- 결과 상태를 안전 보장으로 오해하는 비율 20% 이상
- 두 차례 문구 실험 후에도 가격 관심이 10% 미만

## 8. 실행 후 산출물

- 참가자별 점수표
- 브라우저 이벤트 JSON
- 핵심 인용문은 참가자 ID와 함께 요약
- 주요 실패 장면 스크린샷 또는 타임스탬프
- `Go / Pivot / Stop` 한 페이지 결정 메모

실제 참가자 데이터가 없는 현재 단계에서는 Phase 6를 완료로 표시하지 않는다.
