## 섹션 11. 자유 탐색 추가 발견

**발견 1** 🔴 홈 Recent Scans가 스캔 단위가 아닌 요리 단위로 적재됨
재현: 1번 스캔 → 3개 요리가 각각 별개 칩으로 나열됨. 동일 스캔 결과인데도 같은 아이콘 3개가 뜨고, 서로 다른 칩처럼 보여 혼란스러움.
예상: 스캔 1건 = 칩 1개 (대표 요리명 표시), 히스토리 구조(`resultKey` 기준)로 합쳐야 함.

**발견 2** 🟠 에러 메시지 언어 혼용
`/loading-scan` 진입 시 "문제가 발생했습니다"(한국어) + "No image or text provided. Please try again."(영어) 혼용 노출.

**발견 3** 🟠 히스토리가 스캔 단위가 아닌 요리 단위 나열
히스토리도 마찬가지로 1번 스캔의 3개 요리가 각각 별도 행으로 표시됨. 동일 `resultKey`를 가진 항목들을 그룹핑하거나, 명세의 `ScanHistoryItem` 구조로 정규화 필요.

**발견 4** 🟡 `html lang="en"` 고정
한국어 앱인데 lang 속성이 en. 스크린리더 TTS 발음에 영향. `output_language` 설정에 따라 동적으로 바꾸거나 기본값을 `ko`로 변경 권장.

**발견 5** 🟡 온보딩 슬라이드 2 진입 시 언어가 English로 기본 선택됨
브라우저 언어가 한국어이지만 English가 선택된 상태로 시작. 브라우저 언어 감지가 동작하지 않는 것으로 보임.

### 추가 발견 이슈

**🔴 P0 — 크레딧 차감 서버 검증 미구현**
텍스트 스캔(0.5크레딧 차감 정책) 후에도 크레딧이 9회 그대로 유지됩니다. API 키 직접 사용 시 클라이언트 크레딧 로직이 바이패스되는 것으로 보입니다. 기능 명세 섹션 4.3에서 "출시 블로커"로 명시된 항목으로, 서버 사이드 차감 검증 미구현 상태입니다.

**🟠 P1 — pronunciation 필드 경로 명세 불일치**
명세: `dishes[].pronunciation`
실제 API 응답: `dishes[].translation.pronunciation`
현재 UI는 올바르게 표시되고 있으나, 향후 다른 컴포넌트에서 참조 시 혼동 가능성이 있습니다. 명세와 구현 중 하나를 기준으로 통일 필요합니다.

**🟠 P1 — Stripe 미연결 (개발 환경)**
페이월 옵션 선택 시 Stripe Checkout으로 이동하지 않고 유료 콘텐츠가 바로 열립니다. 개발 환경 기준 미구현 상태로, 출시 전 필수 연동 필요합니다.

**🟡 P2 — Fun Fact 언어 고정 (영어)**
