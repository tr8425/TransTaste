# API 비용 절감안 (2026-10-16)

목표: 메뉴 분석 품질을 유지하거나 높이면서 스캔 1회당 API 비용을 줄인다. C1~C7은 검토안이고, 실제로 적용한 내용은 아래 "적용 내역"에 적는다.

## 현재 구조

- 1단계 `/api/analyze`: 메뉴 전체(사진 최대 10장 또는 텍스트)를 보내 요리 목록 JSON을 받는다. `max_tokens` 8192, 스트리밍.
- 2단계 `/api/analyze/detail`: 사용자가 요리 하나를 누를 때마다 호출된다. **메뉴 전체(사진 포함)를 다시 보낸다.** `max_tokens` 4096.
- 프롬프트 캐싱은 system 프롬프트에만 걸려 있고, 메뉴 사진에는 없다.
- 결과 캐시: Upstash Redis 30일. 메뉴 단위 키(1단계)와 메뉴+요리 단위 키(2단계)를 쓴다.
- 모델: `claude-sonnet-5-5` (`ANTHROPIC_MODEL`로 변경 가능). 2026-10-16까지 쓰던 `claude-sonnet-4-20250514`는 종료되었다.

## 측정값 (count_tokens, 과금 없음)

| 항목 | 토큰 |
|---|---|
| 1단계 system 프롬프트 | 약 1,807 |
| 2단계 system 프롬프트 | 약 1,280 |
| 메뉴 사진 1장 (1600px로 압축, Anthropic이 1568px 기준으로 다시 줄임) | 약 2,400 (가로×세로÷750로 추정) |

출력 토큰은 요리 1개당 약 150~250개로 추정한다 (번역, 알레르기, 가격 등 필드 포함). 30개 요리 메뉴면 출력이 약 6,000 토큰이다.

## 가격 (2026-10 기준, Anthropic 가격 페이지)

| 모델 | 입력 / 100만 토큰 | 출력 / 100만 토큰 |
|---|---|---|
| Sonnet 5.5 | $2 | $10 |
| Haiku 5.5 (프롬프트 10만 토큰 이하) | $0.10 | $0.50 |
| (종료) Sonnet 4 | $3 | $15 |

Sonnet 5.5의 캐시 읽기는 입력 단가의 5%로 안내되어 있다. 적용 전에 가격 페이지를 다시 확인한다.

## 1회 비용 추정 (사진 3장, 요리 30개 메뉴)

| 호출 | Sonnet 5.5 | Haiku 5.5 |
|---|---|---|
| 1단계 스캔 (입력 약 9,000, 출력 약 6,000) | 약 $0.08 | 약 $0.004 |
| 2단계 상세 1회 (입력 약 9,000, 출력 약 400) | 약 $0.02 | 약 $0.001 |
| 상세 5회를 누르는 사용자 1명 합계 | 약 $0.19 | 약 $0.01 |

상세를 5번 누르면 상세 비용(약 $0.10)이 스캔 비용(약 $0.08)보다 커진다. 사진을 매번 다시 보내기 때문이다. 현재 잔액 약 $2.8은 Sonnet 기준으로 이런 사용자 15명 정도에 해당한다.

## 절감안 (효과 큰 순)

### C1. 상세 요청에 사진을 다시 보내지 않기 (품질 영향 거의 없음)
- 상세는 요리 하나의 맛, 재료, 먹는 법 같은 지식 위주라 메뉴 사진이 필요한 경우가 드물다.
- 1단계 결과에서 그 요리의 JSON(원문, 번역, 카테고리, 가격, 알레르기)과 식당 종류만 보낸다.
- 상세 1회 입력이 약 9,000에서 약 1,500 토큰으로 줄어든다. 상세 비용 약 70~80% 감소.
- 사진이 꼭 필요한 경우(이름만으로 알 수 없는 메뉴)를 위해 사진 첨부 경로는 남겨 둔다.

### C2. 상세는 Haiku 5.5로 (품질 비교 후 결정)
- 상세는 이미 1단계가 식별한 요리에 대한 설명이라 작은 모델로도 충분할 가능성이 크다.
- C1과 합치면 상세 1회 비용이 약 $0.0004로 내려간다.
- 결정 전에 C5의 비교 평가를 먼저 한다.

### C3. 요리 단위 공유 캐시
- 지금 상세 캐시는 "메뉴+요리" 키라서 같은 라멘이라도 식당이 다르면 다시 호출한다.
- 요리 이름(정규화), 출력 언어, 알레르기 설정으로 키를 만들면 인기 요리는 거의 매번 캐시에서 나간다.
- `src/lib/food-database.ts`의 정적 데이터로 먼저 답하고 없을 때만 호출하는 방식도 함께 검토한다.
- 주의: 후속 수정 F1(비라틴 문자 정규화 결함)을 먼저 고쳐야 한다.

### C4. 메뉴 사진 프롬프트 캐싱
- C1을 하지 않는 경우의 대안이다. 1단계 요청의 사진 블록에 `cache_control`을 걸면, 5분 안의 상세 요청은 사진 토큰을 5% 가격으로 읽는다.
- C1을 하면 효과가 작아지므로 둘 중 하나만 고른다. C1이 더 단순하고 효과도 크다.

### C5. 1단계 모델 선택은 평가 후 결정
- 1단계는 사진 OCR과 번역, 알레르기 판정이 함께 들어 있어 품질 위험이 가장 크다.
- 메뉴 10개 내외(일본어, 태국어, 중국어, 베트남어, 한국어, 스페인어, 손글씨, 저조도 사진 포함)로 Sonnet 5.5와 Haiku 5.5를 비교한다.
- 기준: 요리 누락 수, 번역 오류, 알레르기 누락(가장 중요), 가격 인식.
- 평가 비용은 Sonnet과 Haiku 각 1회씩 약 $1 이내로 예상한다. 실행 전 사용자 승인 필요.
- 결과에 따라 "텍스트 메뉴는 Haiku, 사진 메뉴는 Sonnet" 같은 분기도 가능하다.

### C6. 큰 메뉴 처리 (품질 향상)
- `max_tokens` 8192에서는 요리 약 35개를 넘는 메뉴가 잘린다 (`E_MAX_TOKENS`).
- 출력 단가는 같으므로 상한을 올려도 작은 메뉴의 비용은 늘지 않는다. 큰 메뉴는 끝까지 받게 되어 품질이 좋아진다.
- 하루 전체 상한(F2)과 함께 둔다.

### C7. 하루 전체 상한과 콘솔 한도 (F2)
- Redis에 하루 호출 수 상한을 두고, 넘으면 관리자 외에는 503으로 막는다.
- Anthropic 콘솔에서 월 사용 한도를 건다.

## 권장 순서

1. F1(캐시 정규화) 수정
2. C1(상세에 사진 빼기). 품질 위험이 낮고 효과가 크다.
3. C7 하루 상한
4. C5 평가를 거쳐 C2(상세 Haiku) 결정, 이어서 1단계 모델 결정
5. C3 요리 단위 캐시, C6 큰 메뉴 처리

## 적용 내역 (2026-10-16 오후)

### 원인: Sonnet 5.5의 기본 추론(thinking)
- Sonnet 5.5는 응답 전에 추론을 하고, 추론 토큰이 `max_tokens`와 요금에 함께 잡힌다. 화면에는 나오지 않는다.
- 홍콩 메뉴 사진(약 70개 항목, 90도 누운 사진)에서 추론에 약 12,000토큰을 쓰고 요리 33개에서 잘렸다(100초). `max_tokens` 1,500으로 확인했을 때 1,500토큰 전부가 추론이었고 텍스트는 0자였다.
- 추론을 끄면(`thinking: { type: "between_tools" }`, 이 모델에서 `disabled`는 400 오류) 같은 사진이 49초, 출력 7,882토큰에 66개로 끝났다.
- 모든 호출에서 끈다. `ANALYSIS_THINKING=adaptive`로 되돌릴 수 있다.
- 앞에서 쓴 "요리 1개당 출력 150~250토큰" 추정은 맞았다. 실측은 목록 단계 기준 요리당 약 113토큰이다.

### 목록 먼저, 분석은 나중에 (C6 대체)
- 스캔은 목록 단계(이름, 번역, 가격)만 스트리밍한다. 요리마다 `analysis_pending`이 붙는다.
- 결과 화면이 `/api/analyze/enrich`로 알레르기, 식단, 칼로리를 20개씩, 동시에 3개 요청으로 채운다. 요청과 응답은 요리별 `item_id`로 맞춘다.
- 분석 전 요리는 어디서나 "직원 확인 필요"로 보인다. "안전"으로 보이지 않는다.
- `max_tokens`는 16,000(`ANALYSIS_MAX_TOKENS`)이고, 잘려도 완성된 요리까지는 결과로 보여준다.
- 목록 캐시 키에는 사용자 프로필을 넣지 않는다(모든 사용자가 공유). 분석 캐시 키에는 프로필과 요리 목록을 넣는다.
- 일일 상한: `DAILY_ENRICH_LIMIT` 기본 120, IP당 시간당 60회.

### 사진 방향 자동 보정
- 같은 사진을 바로 세우면 66개가 72개로 늘고, 가격 표본 12개 중 정답이 5개에서 9개로 늘었다.
- 사진을 고르면 512px 썸네일을 `/api/analyze/orient`(Haiku 5.5, `ORIENT_MODEL`)로 보내 시계 방향 각도를 받는다. 미리보기와 업로드에 반영하고, 사용자가 ↻로 바꿀 수 있다. 실패하거나 5초가 넘으면 원래 방향으로 보낸다.
- 비용은 사진 1장당 $0.001 미만으로 예상한다.

### 테스트 방침
- 로컬 QA에서는 API를 호출하지 않는다. 세션 에이전트가 같은 프롬프트로 만든 응답을 fixture 모드(`ANALYSIS_FIXTURE_DIR`, Vercel에서는 꺼짐)로 재생한다.
- 실제 API는 배포 후 확인에만 쓴다.
