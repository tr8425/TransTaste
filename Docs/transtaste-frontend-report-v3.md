## 3. 확정된 네비게이션 구조

v1 구현으로 확정. v2에서도 동일하게 유지.

```
바텀 네비게이션 (BottomNav)
  [Home]  [● Scan]  [History]
           FAB

자동 숨김 라우트: /camera, /loading-scan
```

탭 구성 이유:
- 3탭이 최소 유효 구조 (홈 / 핵심 액션 / 이력)
- Scan FAB는 중앙 돌출 — 앱의 핵심 행동임을 시각적으로 강조
- 식당 대화 / 팁 정보는 독립 탭 아님 → 결과 화면에서 진입 (스캔 컨텍스트 종속)

## 4. 화면별 상세 설계 (v0.3)

### 4.0 온보딩 (v0.2와 동일)

2단계: 앱 소개 → 언어 + 알러지 프리셋 설정. 건너뛰기 가능.

---

### 4.1 홈 화면 (v0.3 갱신)

v1 피드백: 공백 과다(40%) → 히어로 축소 + 콘텐츠 섹션 추가로 해결.

**레이아웃 (상단 정렬, justify-center 제거)**

```
[네비바: TransTaste 로고 | ⚡ 7 left]
[히어로 160px — 최근 스캔 음식 이미지]
[입력 4종: 카메라(메인) / 갤러리 / URL / 텍스트]
[크레딧 카드 | Trip Pass 카드]
[Popular Dishes Nearby — 2×2 그리드]  ← v1 신규 추가
[Recent Scans — 3개 칩]
[BottomNav]
```

| 요소 | 내용 | 우선순위 |
|---|---|---|
| 히어로 | 160px (v1에서 280px→160px 축소 확정) | 필수 |
| 입력 4종 | 카메라(메인 FAB 스타일) / 갤러리 / URL / 텍스트 | 필수 |
| 크레딧 + 패스 | 항상 노출, 소진 전 인지 | 필수 |
| Popular Dishes Nearby | 2×2 그리드, 인기 음식 4개 | 권장 |
| Recent Scans | 최근 3개 칩, 탭 시 /results 라우팅 | 권장 |

**Popular Dishes Nearby 섹션 — 신규 정의 필요**

v1에서 추가됐지만 기획에서 정의가 없었던 섹션. 아래 두 가지 방향 중 결정 필요:

```
방향 A  로컬 큐레이션 — 국가/지역별 인기 음식 하드코딩
         장점: API 비용 없음, 빠름
         단점: 실시간 아님, 위치 정보 불필요

방향 B  위치 기반 실시간 — GPS + 외부 API
         장점: 실제 "근처" 느낌
         단점: 위치 권한 필요, API 비용 추가, 복잡도 증가
```

**MVP는 방향 A 권장.** 국가 감지(메뉴 언어 기반) 후 해당 국가 인기 음식 로컬 데이터 표시.
"Nearby" 레이블은 추후 위치 기반 구현 시까지 "Popular in Japan" 등 국가명으로 대체.

### 4.5 음식 상세 카드 (v0.3 갱신 — CTA 통합)

**v1 피드백 핵심:** "Unlock with Trip Pass" CTA가 3~4회 반복 → UX 피로.

**확정된 패턴:**

```
[음식 사진]
[번역 3종]
[재료 + 알러지]           ← 무료
─────────────────────────
[FlavorRadar   blur]
[FunFact       blur]     ← 유료 구간: blur 그룹으로 묶음
[HowToEat      blur]
─────────────────────────
[단일 CTA 박스]
  "Unlock flavors, facts & more"
  "$2.99 · 7-Day Trip Pass · One-time payment"
  [Trip Pass 시작하기]
  [크레딧 50회 $1.99도 가능 — 텍스트 링크]
```

**원칙:**
- 유료 구간 내 CTA는 딱 1개
- 각 LockedBlock 안에 CTA 넣지 않음 (blur + 잠금 아이콘만)
- 크레딧 대안은 주 CTA 아래 텍스트 링크로 조용하게

### 4.10 에러 화면 (v0.3 갱신)

**에러 UX 원칙 (전체 공통):**
1. 항상 아이콘 + 제목 + 설명 3요소
2. 반드시 대안 액션 1개 이상 제시
3. 토큰 없음: 사용자 탓하는 문구 금지 ("잘못된 입력" 대신 "다르게 시도해볼까요?")
4. 크레딧 차감 여부 명시 (차감 없을 때는 안심 메시지)

| 에러 | 아이콘 | 제목 | 주요 대안 | 크레딧 |
|---|---|---|---|---|
| not_menu | 카메라 X | "메뉴판이 아닌 것 같아요" | 다시 촬영 / 직접 입력 | 없음 (안심 표시) |
| ocr_failed | 카메라 물음표 | "더 선명하게 찍어볼까요?" | 다시 촬영 / 갤러리 / 직접 입력 | 없음 |
| low_confidence | 경고 삼각형 | "일부 항목이 불확실해요" | 결과 표시 + 배너 경고 | 차감됨 |
| camera_unavailable | 카메라 off | "Camera not available" | Choose from Gallery | — |
| network_error | 와이파이 X | "연결을 확인해주세요" | 재시도 / 오프라인 히스토리 | 없음 |

```
결론        위치 기반 완전 제거
```

## 14. 주문서 기능 — 서버에게 보여주기

### 14.1 포지션

실제 POS 연동이나 결제 처리 없음.
회화 프리셋과 동일한 레이어 — 언어 장벽을 화면으로 해결하는 UX.
직접 그 나라 말로 주문하고 싶은 경우 → 회화 프리셋 사용
화면으로 보여주고 확인받고 싶은 경우 → 주문서 보여주기 사용

### 14.2 플로우

```
결과 리스트
    │ [+ 담기] 각 메뉴 카드
    ▼
장바구니 (세션 임시, 앱 종료 시 초기화)
    │ [주문서 보기]
    ▼
주문서 화면 (/order)
    │ [서버에게 보여주기]
    ▼
전체화면 모드 (/order/present)
서버가 직접 확인 후 [확인했어요] 탭 → 주문서 화면으로 복귀
```

### 14.3 언어 분리 원칙

```
주문서 화면 (/order)           → 사용자 언어 (output_language 설정값)
                                  한국인 일본 여행 시: 한국어
                                  메뉴명, 배너, UI 전부 한국어

전체화면 모드 (/order/present) → 현지 언어 (menu_language 감지값)
                                  한국인 일본 여행 시: 일본어
                                  메뉴명 원문 + 배너 일본어
```

두 화면이 사용하는 언어 소스가 다름:

| | 주문서 화면 | 전체화면 모드 |
|---|---|---|
| 언어 소스 | `user_settings.output_language` | `scan_result.menu_language` |
| 배너 언어 | 사용자 언어 | 현지 언어 |
| 메뉴명 | 번역된 이름 (한국어) | 원문 (일본어) + 번역 병기 |
| UI 텍스트 | 사용자 언어 | 최소화 (숫자·아이콘 위주) |

### 14.4 주문서 화면 레이아웃 — 사용자 언어

```
(한국인이 일본 여행 중인 경우)

┌─────────────────────────────────────┐
│  ⚠️ 새우·게 알러지가 있어요         │ ← 한국어, 항상 최상단
│  ⚠️ 비건이에요                      │
├─────────────────────────────────────┤
│  주문 목록                           │
│  • 불고기 덮밥      ×1   ¥1,200    │ ← 번역된 한국어 메뉴명
│  • 된장찌개         ×2   ¥900      │
│  • 공기밥           ×2   ¥200      │
│  [+ 메뉴 추가]                       │
├─────────────────────────────────────┤
│  소계              ¥3,200          │
│  팁 없음 (일본)                     │ ← 팁 문화 데이터 자동
│  합계              ¥3,200          │
├─────────────────────────────────────┤
│  [서버에게 보여주기  →]              │ ← 전체화면 모드 진입
│  [회화 프리셋으로 직접 주문하기]     │
└─────────────────────────────────────┘
```

### 14.5 전체화면 모드 — 현지 언어

```
(서버가 읽는 화면 — 일본어)

┌─────────────────────────────────────┐
│  ⚠️ エビ・カニアレルギーがあります  │ ← 일본어, 크고 강조
│  ⚠️ ヴィーガンです                  │
├─────────────────────────────────────┤
│  ご注文                              │
│  • プルコギ丼        ×1   ¥1,200   │ ← 원문 일본어 메뉴명
│    (불고기 덮밥)                    │ ← 한국어 번역 병기 (작게)
│  • 味噌汁            ×2   ¥900     │
│  • ご飯              ×2   ¥200     │
├─────────────────────────────────────┤
│  合計              ¥3,200          │
├─────────────────────────────────────┤
│           [確認しました]             │ ← 서버가 탭
└─────────────────────────────────────┘

UI 특성:
  글씨 크기 대폭 확대 (배너 24px, 메뉴명 20px)
  배경 흰색 고정 (다크모드 무시)
  네비바 / 탭바 숨김
  화면 꺼짐 방지 (wake lock API)
  하단 확인 버튼 현지어 ("確認しました" / "Confirmed" 등)
```

### 14.6 알러지 / 식이 제한 배너

프로필 프리셋 + 스캔 결과 감지 내용 통합 표시.

우선순위 순서:
1. 생명 위협 알러지 (심각도 높은 순)
2. 일반 알러지
3. 종교적 제한 (할랄, 코셔, 힌두 소고기 금기)
4. 신념적 제한 (비건, 채식, 금주)

같은 내용을 두 가지 언어로 각각 생성:

| 프리셋 | 주문서 화면 (사용자 언어 = 한국어) | 전체화면 (현지 언어 = 일본어) |
|---|---|---|
| 갑각류 알러지 | 새우·게 알러지가 있어요 | エビ・カニアレルギーがあります |
| 비건 | 동물성 식품을 먹지 않아요 | ヴィーガンです |
| 할랄 | 할랄 음식만 먹어요 | ハラール食のみです |
| 힌두 (소고기) | 소고기를 먹지 않아요 | 牛肉は食べられません |

배너 문장은 로컬 JSON — API 호출 없음.
CartState에 `menu_language` 저장해뒀다가 전체화면 진입 시 참조.

### 14.6 식이 신념 프리셋 추가

온보딩 2단계 알러지 설정에 추가.

```
기존: 알러지 14종 (EU 표준)
추가: 식이 신념
  비건         — 동물성 식품 전체 (고기·생선·유제품·달걀)
  채식         — 육류만 제외
  할랄         — 돼지고기·알코올 금기
  코셔         — 유대교 식이 규정
  힌두 (소고기) — 소고기 금기
  금주         — 알코올 포함 음식 주의
```
