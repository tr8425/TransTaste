# TransTaste 상품성 검토

> 작성일: 2026-07-30
> 검토 기준: 현재 코드베이스, 공개 프로덕션, 기존 기획 문서, 2026년 경쟁 제품 현황

## 1. 결론

TransTaste는 지금 바로 Supabase·Stripe와 네이티브 앱에 투자할 단계는 아니다. 그러나 폐기하기에는 핵심 사용 흐름과 구현 자산이 충분하다.

권고안은 다음과 같다.

> 범용 메뉴 번역 앱으로는 투자하지 않는다.
> “식이 제한이 있는 해외여행자의 안전한 메뉴 선택과 현지어 주문 도우미”로 포지셔닝을 좁혀 2주간 검증한다.
> 검증 지표가 통과될 때만 계정·결제·서버 크레딧 시스템에 투자한다.

### 종합 평가

| 항목 | 평가 | 판단 |
|---|---:|---|
| 문제의 현실성 | 8/10 | 해외 식당에서 실제로 반복되는 문제 |
| 시장 경쟁력 | 4/10 | Lens, ChatGPT, 전문 앱과 경쟁 |
| 현재 차별성 | 5/10 | 개별 기능보다 전체 주문 흐름에 가능성 |
| 첫 사용자 접근성 | 6/10 | 무가입 접근은 좋으나 온보딩과 신뢰 장벽 존재 |
| 시각적 완성도 | 6/10 | 일관된 프로토타입이나 유료 제품 신뢰감은 부족 |
| 안전·신뢰성 | 4/10 | AI 추정과 확인 사실의 경계가 약함 |
| 수익화 가능성 | 5/10 | 여행 패스는 적합하지만 결제 의향 미검증 |
| 검증 후 성장 가능성 | 7/10 | 특정 타깃에서 문제 강도가 높음 |

현재 상품성은 약 5.5/10이다. 포지셔닝과 핵심 경험을 좁히고 실제 사용자 검증을 통과하면 7/10 수준까지 개선할 수 있다.

## 2. 현재 제품 상태

### 기술 상태

- Next.js 14 App Router 기반 PWA
- 프로덕션: `https://transtaste.vercel.app`
- ESLint 통과
- i18n 한국어·영어 758개 키 동기화
- 프로덕션 빌드 성공, 정적 페이지 113개 생성
- Vercel 프로젝트 연결 완료
- Supabase, Stripe, Anthropic, Upstash 운영 환경변수 미설정
- 프로덕션 AI 분석은 mock 결과 반환
- 결제는 실제 Stripe 세션 대신 성공 URL을 반환
- 최신 프로덕션 배포는 2026-05-31 생성본

### 제품 자산

- 카메라, 갤러리, URL, 텍스트 입력
- 메뉴 번역과 음식 설명
- 알레르기·식단 위험 표시
- 대체 음식, 맛, 칼로리, 문화 정보
- 환율 표시
- 주문 장바구니
- 점원에게 보여주는 현지어 주문 화면
- 8개 언어 회화
- 국가별 팁 문화와 식당 가이드
- PWA와 SEO용 음식·국가 페이지

### 현재 사업 루프의 단절

```text
방문
  → 온보딩
  → 스캔
  → mock 결과
  → localStorage 크레딧
  → 결제처럼 보이는 로컬 성공 처리
  → 사용자 행동 측정 없음
```

현재는 사용자가 가치를 느끼는지, 어디서 이탈하는지, 결제 의향이 있는지를 판단할 데이터가 없다. 기능 부족보다 이 학습 루프의 부재가 프로젝트 정체의 핵심 원인이다.

## 3. 시장성과 경쟁

메뉴 번역은 이미 혼잡한 시장이다. 경쟁 제품은 번역뿐 아니라 알레르기, 식단 필터, 음식 사진, 통화 환산, 주문 목록, 현지어 표시, 그룹 주문을 제공한다.

무료 대체재도 강력하다.

- Google Lens: 즉시 카메라 번역
- ChatGPT: 이미지 기반 음식 설명과 질의응답
- Google Translate 및 OS 번역 기능

따라서 “메뉴를 찍으면 번역한다”는 독립적인 구매 이유가 되기 어렵다.

TransTaste의 상품 기회는 다음의 전체 흐름에 있다.

```text
먹을 수 있는 요리를 찾는다
  → 위험과 불확실성을 이해한다
  → 대체 메뉴를 고른다
  → 주문 목록을 만든다
  → 점원에게 현지어로 정확하게 전달한다
```

## 4. 권장 포지셔닝

### 기존

> Scan any menu, understand every dish.

장점은 명확하지만 Google Lens와 직접 비교되는 범용 문구다.

### 권장

> 해외 식당에서 먹을 수 있는 메뉴를 찾고, 현지어로 안심하고 주문하세요.

영문 예시:

> Find what you can eat. Order it clearly in the local language.

### 초기 타깃 우선순위

1. 채식·비건 해외여행자
2. 할랄 등 종교적 식이 제한 여행자
3. 특정 재료를 피하는 여행자
4. 음식 알레르기가 있는 여행자

알레르기는 문제 강도가 가장 높지만 안전·법적 기대치도 높다. 초기 검증은 채식·할랄 사용자를 중심으로 시작하고, 알레르기는 “AI 참고 정보 + 직원 확인 도구”로 제한하는 편이 안전하다.

## 5. 수익화 검토

### 적합한 모델

TransTaste는 매일 사용하는 서비스보다 여행 중 집중 사용하는 서비스다. 반복 구독보다 여행 기간 또는 스캔 단위 결제가 적합하다.

권장 가격 실험:

| 상품 | 실험 가격 |
|---|---:|
| 무료 | 실제 메뉴 분석 2회 |
| 10회 스캔 팩 | $1.99 |
| 7일 여행 패스 | $3.99 |
| 30일 여행 패스 | $7.99 |
| 동행자 공유 7일 패스 | $5.99 |

현재의 50회 $1.99는 대부분의 여행자에게 사실상 무제한이라 7일 패스의 구매 이유를 약화한다.

### 투자 보류 사유

- 결제 CTA 클릭률과 지불 의향이 측정되지 않음
- 실제 AI 품질과 응답 시간 검증이 부족함
- 여행 앱 특성상 재방문 주기가 김
- 무료 범용 번역 도구가 강력함
- 현재 인증·결제·크레딧이 모두 로컬 상태임

Stripe를 연결하기 전에 가격 CTA와 잠금 해제 행동을 측정해야 한다.

## 6. 사용자 접근성

### 강점

- 회원가입 없이 진입 가능
- 카메라 외에도 갤러리·URL·텍스트 입력 지원
- 모바일 우선
- PWA 설치 가능
- 다양한 식당 보조 도구 제공

### 문제

- 식당에서 급한 사용자에게 온보딩 슬라이드와 사전 설정이 길다.
- “10 free scans”가 계정 혜택처럼 보이지만 실제로는 브라우저 저장소 기반이다.
- 기기 변경이나 브라우저 데이터 삭제 시 기록과 설정이 사라진다.
- AI 추정, 메뉴 명시 정보, 교차오염 가능성이 충분히 구분되지 않는다.
- 네트워크가 불안정하면 핵심 분석이 중단된다.
- 첫 화면의 여러 기능이 핵심 CTA와 경쟁한다.

### 권장 첫 경험

```text
홈
  → 즉시 촬영 또는 샘플 메뉴 선택
  → 분석 시작
  → 분석 중 식이 제한 1회 질문
  → 첫 결과 제공
  → 결과 사용 후 설정 저장 제안
```

설정 중심 온보딩이 아니라 성공 경험 중심 온보딩으로 바꾼다.

## 7. 비주얼 및 브랜드

### 강점

- 크림·코랄·브라운 색상은 음식·여행 서비스와 잘 맞는다.
- 카드와 둥근 모서리가 모바일 사용에 자연스럽다.
- 위험 상태를 색상으로 구분한다.
- 전반적인 화면 톤이 일관된다.

### 약점

- 이모지 비중이 높아 유료 제품보다 프로토타입처럼 보인다.
- 홈에 실제 메뉴가 분석 결과로 바뀌는 증거가 없다.
- 알레르기·식이 제한 기능의 신뢰 근거가 보이지 않는다.
- 기능이 많지만 대표 기능을 기억하기 어렵다.
- 브랜드 고유 아이콘과 그래픽 자산이 부족하다.
- 결과 화면이 정보 중심이라 실제 주문 결정이 느려질 수 있다.

### 비주얼 개선 우선순위

1. 홈에 실제 메뉴와 분석 결과의 전후 비교 배치
2. 이모지를 일관된 아이콘 세트로 교체
3. 대표 결과 카드 3종 노출: 피하기, 확인 필요, 선택 가능
4. 점원 표시 화면을 대표 기능으로 승격
5. 여행 도구와 SEO 콘텐츠를 홈 하단으로 이동
6. 지원 언어, 감지 항목, 평균 처리 시간 등 구체적 근거 제공
7. 색상 외에도 아이콘과 문구로 위험 상태 전달

## 8. 신뢰와 안전

AI가 알레르기 안전을 보증하는 것처럼 보이면 안 된다.

권장 상태 체계:

| 상태 | 의미 |
|---|---|
| 피하기 | 메뉴 또는 일반 조리법상 제한 재료 포함 가능성이 높음 |
| 직원 확인 필요 | 조리법, 소스, 육수, 교차오염을 확인해야 함 |
| 명시된 위험 없음 | 현재 메뉴 정보에서 위험 재료가 발견되지 않았지만 안전 보장은 아님 |

`safe`라는 표현은 피하고 모든 결과에서 직원 확인 경로를 제공한다.

상품화 전 최소 검증:

- 실제 메뉴 100~300개 평가 세트
- 메뉴 항목 인식률
- 알레르기·식단 제한 recall
- 잘못된 안전 판단 비율
- 평균 첫 결과 시간
- 여러 장 메뉴와 저조도 사진 성공률

## 9. 투자 의사결정 게이트

### 2주 검증에 투자

- 핵심 포지셔닝 변경
- 실제 메뉴 데모 3종
- 성공 경험 중심 플로우
- 최소 행동 분석
- 결제 CTA 실험
- 사용자 테스트 10~20명

### 아직 보류

- 완전한 Supabase 인증
- Stripe Webhook과 정산
- 서버 크레딧 원장
- 네이티브 앱 출시
- 여행 콘텐츠 대량 확장
- 그룹 주문·소셜·B2B 확장
- 전면 브랜드 리뉴얼

### 통과 기준

| 지표 | 기준 |
|---|---:|
| 방문 → 촬영/샘플 시작 | 25% 이상 |
| 분석 시작 → 결과 도달 | 70% 이상 |
| 첫 결과 중앙값 | 15초 이하 |
| 결과 → 주문 담기/점원 표시 | 25% 이상 |
| 무료 한도 → 가격 CTA 클릭 | 10% 이상 |
| 명시적 결제 의향 | 5% 이상 |
| 다음 여행 재사용 의향 | 테스트 사용자 40% 이상 |
| Lens/ChatGPT 대비 선호 | 제한식 사용자 과반 |

이 기준 중 핵심 지표가 통과하면 Supabase·Stripe 투자를 진행한다. 통과하지 못하면 포지셔닝을 한 차례 수정하고, 두 번째 검증에서도 실패하면 프로젝트를 유지보수 모드로 전환한다.

## 10. 최종 판단

TransTaste의 성공 조건은 더 많은 기능이 아니다.

> 사용자가 이 앱을 통해 무엇을 주문할지 결정하고, 직원에게 자신의 제한 사항과 주문을 전달할 수 있었는가?

향후 작업은 이 질문을 측정하고 개선하는 데 집중한다.
