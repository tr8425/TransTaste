### 기획 블록 4: 콘텐츠 & 아키텍처 고도화

**4-Layer 캐싱 구조 확정:**
```
L1: Redis 정확 매칭 (SHA256, TTL 30일)   히트율 55~60%
L2: Redis 정규화 매칭                     +10~15%
L3: Claude Prompt Caching (5분)
L4: Claude API 호출
```

**브랜드명 처리:**
- "박가부대찌개" → brand_part / food_part 분리
- 브랜드는 번역하지 않고 보존

**result_json 핵심 필드 확정:**
- translation (literal / meaning / english)
- allergen_summary (4단계)
- fun_fact / fun_fact_detail / warning / disclosure
- price / currency / price_display
- has_customization / options
- is_seasonal

### 기획 블록 7: "음식 이름을 찍는다" 케이스 전체 정의

**핵심 확장:**
```
메뉴판 → 호텔 룸서비스 → 기내식 → 노점 → 광고판
→ "여행의 모든 식사 순간"으로 범위 확장
```

**케이스 분류:**
- 핵심 (MVP): 메뉴판 6종 + 호텔/기내식 추가
- 확장 (V2): 음식 사진, 이미지 URL
- 경계: 포장식품 → 안내 메시지로 소프트 커버
- 제외: 영수증 금액 분석, 식품 성분 상세

**마케팅 포인트 별도 관리 결정.**

---

### 기획 블록 8: 메뉴 옵션 & 커스터마이징

**서브웨이형 vs 전골/사리형 분류:**
- 이미지에 선택지 있음 → options 배열로 파싱
- 이미지에 없음 → has_customization: true + 대화 프리셋 연결

### 기획 블록 9: 알러지 시스템 행동 도우미로 확장

**4단계 위험도 확정:**
```
main     → ❌ 강한 경고 + 대안 메뉴 추천
sub      → ⚠️ "빼달라고" 프리셋 연결
possible → 〰️ "들어가나요?" 프리셋 연결
none     → ✅ 조용히 표시
```

**대안 메뉴 추천:** 동일 스캔 내에서만, 외부 DB 없음.

### 기획 블록 10: 주문서 & 서버에게 보여주기

**포지션 확정:**
- 실제 POS 연동 없음 — 회화 프리셋과 동일 레이어
- 화면 보여주기로 언어 장벽 해결

**언어 분리 원칙 (핵심 맹점 발견):**
```
주문서 화면     → output_language (한국어)
전체화면 모드   → menu_language (일본어)
```
처음 설계에서 두 언어가 혼재된 오류 발견 → 즉시 수정.

**식이 신념 프리셋 추가:**
비건 / 채식 / 할랄 / 코셔 / 힌두(소고기) / 금주

### 기획 블록 11: Fun Fact 톤 가이드

**핵심 원칙:**
- 부정적 유래 → 긍정 재프레이밍
- 성적 콘텐츠 완전 차단 (정력, 스태미나 등)
- 장어구이/복분자주: 보양식·지역 특산물 각도로만
- 복분자주 "요강 뒤집힌다" 유래: 성적 아님 → fun_fact_detail 접기 허용

**fun_fact_detail 접기 패턴 신설:**
식욕 저하 가능한 사실을 선택적 노출로 처리.
적용: ホルモン 어원, 빈대떡 유래, 부대찌개 탄생 배경 등.

**disclosure 필드 신설:**
필터링이 아닌 문화권 맥락 강화. output_language 기반 강도 조정.

```

```

**플라이휠:**
사용자 증가 → hit_count 축적 → 콘텐츠 자동 생성 → AI 인용 → 신규 유입

**수익화 재검토:**
- Free 7회 (구현) vs 기획 10회 → 브리핑 기준 7회로 확정

- Long Trip 구독 → 비여행 기간 이탈 리스크 → 보류

### 사업 리스크 감사

**주요 지적 8가지:**
1. 시장 규모 근거 없음 (TAM/SAM/SOM 미계산)
2. 핵심 가정 5개 미검증
3. 경쟁 분석 정적 (Google 언제든 추가 가능)
4. LTV $11.98로 CAC 감당 어려움
5. 캐싱 역설 (히트율↑ → 전환압력↓)
6. 인디 실행 가능성 → Claude Code로 반박
7. 법적 리스크 전무 (알러지 제품 책임, GDPR)
8. 사용자 신뢰 형성 문제

**Claude Code 개발 속도 실측:**
```
일반 개발자 1개월 = Claude Code 하루
일반 개발자 1~2개월 = 프롬프트 5회 수준
→ 인디 실행 가능성 감사 지적 완전 반박
```
