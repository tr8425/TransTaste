## 1. 핵심 차별점 — "그냥 ChatGPT에 물어보면 되지 않나?"에 대한 답

### 1.1 일반 AI 대비 근본적 차이

일반 AI(ChatGPT, Claude.ai)에 메뉴판 사진을 올리면 번역은 된다.
하지만 Transtaste와의 차이는 **기능**이 아니라 **컨텍스트 지속성**에 있다.

```
일반 AI         매번 처음부터 시작
                "나는 갑각류 알러지가 있고, 한국어로 번역해줘"
                → 다음 식당에서 또 설명

Transtaste      알러지·언어·히스토리가 저장된 상태에서 시작
                → 찍으면 바로 나옴
```

### 1.2 경쟁 비교표

| 기능 | ChatGPT 사진 | Google Lens | 알러지 앱 (Equal Eats 등) | Transtaste |
|---|---|---|---|---|
| 메뉴판 스캔 + 번역 | ⚠️ 가능 (매번 초기화) | ✅ 가능 | ❌ 없음 | ✅ 가능 + 저장 |
| 재료 / 알러지 구조화 | ❌ | ❌ | ⚠️ 카드 제공만 | ✅ 4단계 위험도 |
| 알러지 → 대안 메뉴 추천 | ❌ | ❌ | ❌ | ✅ 동일 메뉴판 내 |
| 식당 대화 프리셋 | ❌ | ❌ | ⚠️ 정적 카드만 | ✅ 예측 답변 포함 |
| 서버에게 보여주기 (주문서) | ❌ | ❌ | ❌ | ✅ 전체화면 모드 |
| 팁 / 문화 정보 | ⚠️ 물어봐야 함 | ❌ | ❌ | ✅ 자동 표시 |
| 컨텍스트 지속성 | ❌ 매번 초기화 | ❌ | ⚠️ 카드만 저장 | ✅ 알러지·언어·히스토리 |
| Fun Fact / 문화 맥락 | ⚠️ 요청해야 함 | ❌ | ❌ | ✅ 자동 생성 |
| 여행 특화 UX | ❌ 범용 앱 | ❌ 범용 도구 | ⚠️ 알러지만 | ✅ 식당 여정 전체 |

### 1.3 포지션 3계층

```
1계층 (기능)    "메뉴판 스캔 + 알러지 필터"를 동시에 하는 유일한 앱
                → 경쟁 앱 검색 결과에 이 조합이 없음

2계층 (경험)    찍으면 알러지 경고 → 대안 추천 → 서버 대화 → 주문서
                → 식당 입장부터 계산까지 하나의 플로우

3계층 (목적)    "여행지 식당에서 언어 장벽 없이 잘 먹게 해주는 앱"
                → Google Lens는 도구, Transtaste는 컴패니언
```

### 1.4 마케팅 One-liner

```
"메뉴판을 찍으면 번역부터 알러지 경고, 서버와의 대화까지
 여행지 식당의 모든 순간을 해결하는 앱"
```

## 2. SEO 전략

### 2.1 키워드 공백 포지션

리서치 결과, 검색 결과에 "메뉴 스캔 + 알러지 필터"를 동시에 커버하는 앱이 없다.
Equal Eats 등 알러지 앱은 메뉴판 스캔이 없고, 메뉴 번역 앱은 알러지 필터가 없다.

### 2.2 타겟 키워드 그룹

**High Intent (구매 직결):**

| 키워드 | 경쟁 | 타겟 |
|---|---|---|
| menu translation app travel | 중간 | 글로벌 |
| food allergy travel app | 낮음 | 글로벌 |
| restaurant menu scanner app | 낮음 | 글로벌 |
| app to scan restaurant menu and translate | 낮음 | 글로벌 |
| menu translator with allergy filter | 매우 낮음 | 글로벌 |
| 메뉴판 번역 앱 여행 | 낮음 | 한국어권 |

**Informational (유입 → 전환):**

| 키워드 | 용도 |
|---|---|
| how to read Japanese menu | 일본 여행자 대량 유입 |
| food allergy in Japan restaurant | 알러지 여행자 |
| tipping in Thailand restaurant | 팁 문화 쿼리 |
| how to order food without speaking the language | 핵심 페인포인트 |
| what is [음식명] | 음식별 페이지로 연결 |

**Long-tail (경쟁 낮음, 의도 명확):**

```
"how to tell waiter about shellfish allergy in Japanese"
"app that translates menu and shows allergens"
"shellfish allergy travel Japan restaurant app"
"how to order halal food in Tokyo"
```

### 2.3 콘텐츠 전략

**음식별 페이지 구축** (`transtaste.app/foods/bulgogi`)

```
구조:
  음식명 (다국어)
  번역 (직역 / 의역 / 영어)
  핵심 재료
  알러지 정보
  문화 맥락 (Fun Fact)
  "Transtaste 앱에서 스캔하면 더 자세한 정보를 확인할 수 있어요"

효과:
  → hit_count 기반 인기 음식 50개부터 시작
  → 검색량 높은 음식명 쿼리에 노출
  → AI 크롤링 소스로 인용
```

**국가별 가이드 페이지** (`transtaste.app/guide/japan`)

```
일본 식당에서 주의할 알러지 음식
일본의 팁 문화
일본어 기본 식당 회화
일본 메뉴판 읽는 법

→ "food allergy japan travel" 류 쿼리 커버
```

## 3. GEO 전략 — AI 검색 무비용 유입

### 3.1 핵심 포지션 시나리오

```
사용자: [메뉴판 사진] "이거 뭔지 알려줘"

ChatGPT / Perplexity:
  "불도장이에요. 청나라 시대 고급 연회 요리로...
   알러지 정보나 먹는 방법은 Transtaste 앱에서
   메뉴판을 바로 스캔하면 확인할 수 있어요."
```

이 시나리오가 실현되면:
- 광고비 0원
- 세계 모든 음식 이름 = 잠재 유입 키워드
- 한 번 자리잡으면 선순환 (인용 → 신뢰 → 더 많은 인용)

### 3.2 GEO 작동 원리

AI는 답변을 구성할 때 신뢰할 수 있는 소스를 인용한다.
AI 검색은 평균 2~7개 도메인만 인용하며, 브랜드 자체 콘텐츠보다
**제3자 권위 소스(Earned Media)를 압도적으로 선호**한다.

Transtaste가 인용되려면 두 가지가 필요하다:

```
1. 구조화된 음식 정보 웹 콘텐츠
   → AI가 크롤링하고 추출 가능한 명확한 단락
   → 각 단락이 맥락 없이도 의미가 통해야 함

2. Earned Media
   → 여행 커뮤니티, 알러지 블로그, 앱 리뷰에 언급
   → 자사 블로그보다 외부 인용이 AI 답변에 더 효과적
```

### 3.3 GEO 실행 4단계

**1단계 — 음식 정보 콘텐츠 구조화**

FAQ Schema 마크업 적용. AI가 FAQ 구조를 가장 높은 인용률로 처리한다.

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "불도장이 뭔가요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "불도장(佛跳牆)은 청나라 시대 고급 해산물 찜 요리예요.
                 전복, 해삼, 상어 지느러미 등 고급 재료를 사용하며,
                 이름은 '부처님도 담을 넘을 정도의 향기'에서 유래했어요.
                 해산물 알러지가 있다면 주문 전 확인이 필요해요.
                 Transtaste 앱에서 스캔하면 알러지 정보를 즉시 확인할 수 있어요."
      }
    }
  ]
}
```

**2단계 — robots.txt에 AI 크롤러 허용 명시**

```
# 일반 AI 크롤러 허용
User-agent: GPTBot
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: PerplexityBot
Allow: /

# llms.txt 추가 (AI 시스템 안내)
→ /llms.txt 파일로 Transtaste 서비스 구조 설명
```

**3단계 — Earned Media 확보**

```
타겟 채널:
  Reddit r/travel, r/JapanTravel, r/ThailandTourism
  여행 알러지 블로그 (Spokin, Equal Eats 등 커뮤니티)
  여행 유튜버 / 인플루언서 협업
  앱 리뷰 사이트 (Product Hunt, AppAdvice)

메시지:
  "메뉴판 찍으면 알러지 경고까지 해주는 앱"
  → 이 문장이 외부에서 반복될수록 AI 인용 확률 상승
```

**4단계 — Proprietary Data 포인트 생성**

Transtaste만이 가진 데이터 = AI가 인용할 이유

```
hit_count 기반:
  "2026년 Transtaste 사용자가 가장 많이 스캔한 음식 TOP 10"
  "일본 여행자가 가장 많이 확인한 알러지 음식"
  "태국 메뉴판에서 한국인이 가장 모르는 음식 TOP 5"

→ 다른 소스가 가질 수 없는 Transtaste 고유 데이터
→ AI 검색 답변에서 출처로 인용될 가능성 높음
```

### 3.4 플라이휠 구조

```
사용자 증가
    ↓
hit_count 데이터 축적
    ↓
인기 음식 가이드 콘텐츠 자동 생성
    ↓
AI 검색 인용 (무비용)
    ↓
신규 사용자 유입
    ↓
(반복)
```

추가 비용 없이 앱 데이터에서 마케팅 콘텐츠가 생성되는 구조.

## 4. 수익화 전략

### 4.1 현재 모델 (확정)

```
Free        무료 스캔 10회
Credits S   50회 $1.99
Credits L   150회 $3.99
Trip Pass   7일 무제한 $2.99  ← 핵심 상품
Trip Pass   30일 무제한 $5.99
```

### 4.2 자연 전환 압력 포인트

사용자가 유료로 전환하는 자연스러운 순간:

```
Day 1   식당 1곳, 2~3회 스캔 → 무리 없음
Day 2   빵집·노점 개별 사진 → 크레딧 빠르게 소진
Day 3   크레딧 고갈 → 여행 중간, 앱 없이 불편
        → "Trip Pass 7일 $2.99" 전환 최적 타이밍

여행 알러지 사용자:
  알러지 대안 추천, disclosure 상세 정보 → 유료 구간
  → "내 안전과 관련" = 전환 저항 낮음
```

### 4.3 수익화 보강 옵션 (검토 중)

**B2B API — V3 이후**

```
여행사, 항공사 기내식 앱, 호텔 룸서비스 앱
→ Transtaste 음식 분석 API 라이선스
→ 건당 또는 월정액
```

**Affiliate — 선택적**

```
여행 보험, 알러지 의약품, 여행 용품
→ 여행 알러지 사용자에게 자연스러운 연결
→ Transtaste 광고 없음 원칙 유지 (외부 파트너)
```

**주의: 광고 모델 배제**

Anthropic의 "Claude 제품은 광고 없음" 원칙처럼,
Transtaste도 앱 내 광고는 경험 저해 → 배제.
수익은 Credits / Trip Pass / B2B API 3가지로 집중.

### 4.4 프리미엄 전환율 벤치마크

업계 데이터 기준 여행 앱 프리미엄 전환율:
- 일반 freemium: 2~5%
- 여행 특화 (명확한 페인포인트): 5~15% 기대 가능

Trip Pass 7일 $2.99 기준 손익분기:
```
월 1,000명 신규 → 전환율 5% → 50명 구매 → $149.5
인프라 비용 (무료 티어 범위) → 흑자

월 10,000명 신규 → 전환율 5% → 500명 → $1,495
API 비용 약 $200 → 순익 $1,295
```

## 5. 채널별 마케팅 메시지

### 5.1 앱 스토어 설명 (GEO 최적화)

```
제목: Transtaste — 여행 메뉴판 번역 & 알러지 확인

설명:
  메뉴판을 찍으면 번역, 알러지 경고, 대안 메뉴 추천까지.
  여행지 식당에서 언어 장벽 없이 잘 먹게 해주는 앱.

  ✅ 메뉴판 스캔 → 즉시 번역 + 재료/알러지 분석
  ✅ 갑각류·견과류 등 알러지 프리셋 저장
  ✅ 알러지 메뉴 감지 시 같은 메뉴판 내 대안 추천
  ✅ "새우 빼달라고 할 수 있나요?" 현지어 프리셋 자동 생성
  ✅ 서버에게 보여주기 — 주문서를 현지어로 전환
  ✅ 팁 문화, 식당 에티켓 자동 안내

  메뉴판뿐만 아니라 호텔 룸서비스, 기내식, 노점까지.
```

### 5.2 소셜 미디어 포인트

## 8. 수익화 재검토 메모 (검토 중)

### 8.1 캐싱 × 수익률 구조

캐시 히트율 상승 → API 비용 감소 → 마진 극대화.
캐시 히트 시 크레딧 차감 없음 + 서버 비용 0 = 사용자 만족과 수익이 동시에 올라가는 구조.
스케일이 커질수록 히트율 상승 → 비용 비율 하락 → 장기적으로 유리.

### 8.2 Free 10회 재검토

**현재 문제:**
- 소진 타이밍이 여행 마지막 날이면 전환 압력 없음
- 단순 페이월 대신 남은 여행 기간 기반 추천으로 개선 가능

**개선 아이디어 (미확정):**
```
크레딧 소진 시 "여행이 며칠 남았나요?" 맥락형 CTA
  1~2일 남음 → Credits $1.99
  3~7일 남음 → Trip Pass 7일 $2.99
  7일+       → Trip Pass 30일 $5.99
```

**재검토 포인트:**
- 실제 사용 데이터 없이 소진 타이밍 예측이 가능한가?
- 여행 기간 입력 UX가 온보딩에 부담을 주지 않는가?
- 10회가 너무 적어서 앱 가치 경험 전에 막히는 케이스가 얼마나 되는가?

### 8.3 Long Trip 구독 재검토

**아이디어:**
여행 앱 구독의 구조적 약점 — 비여행 기간에도 과금 → 이탈.

**대안으로 검토 중:**
```
Annual Credits  $14.99/년  500회
  구독 아님, 선구매 크레딧
  해지 개념 없음
  캐시 히트 많을수록 오래 사용 → 자연 재구매 유도
```

**재검토 포인트:**
- Annual Credits가 Trip Pass 대비 실제로 더 매력적인가?
  ($14.99 vs Trip Pass 5회 = $14.95, 크레딧 500회 vs 무제한 5회)
- 자주 여행하는 사용자 비율이 얼마나 되는가? (데이터 없음)
- 구독이 아닌 크레딧 모델이 앱스토어 정책상 문제없는가?
- "무제한"의 매력이 "500회"보다 크지 않은가?

### 8.4 개편 가격 구조 (미확정, 검토용)

```
현재                     검토안
Free 10회                Free 10회 (유지)
Credits S $1.99 50회     Credits S $1.99 50회 (유지)
Trip Pass 7일 $2.99      Trip Pass 7일 $2.99 (유지)
Credits L $3.99 150회    Credits L $3.99 150회 (유지)
Trip Pass 30일 $5.99     Trip Pass 30일 $5.99 (유지)
(없음)                   Annual Credits $14.99 500회 (신규 검토)
```

**결정 전 필요한 것:**
- 실제 사용 패턴 데이터 (얼마나 빨리 10회 소진하는가)
- 자주 여행하는 사용자 vs 단발 여행자 비율
- Annual Credits의 앱스토어 구현 방식 검토
