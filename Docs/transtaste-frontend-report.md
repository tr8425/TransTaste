## 1. 벤치마킹 → 디자인 결정 매핑

| 레퍼런스 | 인사이트 | Transtaste 적용 |
|---|---|---|
| **Yuka** | 스캔이 "게임처럼 재미있다" — 유저 리뷰 | 로딩 중 Fun Fact 표시, 알러지 태그 색상 강조 |
| **Yuka** | 무료에서 충분히 유용하되, 더 보고 싶게 만드는 경계선 | 재료/알러지 무료, 레이더/Fun Fact/먹는법 유료 잠금 |
| **Google Lens** | 카메라 뷰파인더가 앱 전체 | 홈에서 스캔 화면 직행, 코너 가이드 오버레이 채택 |
| **Google Lens** | 결과가 하단 패널로 자연스럽게 올라옴 | 결과 리스트 → Bottom Sheet 상세 카드 패턴 |
| **빈대떡 인포그래픽** | 재료 아이콘 + 뱃지 레이아웃, 맛 레이더 | 음식 카드에 ingredient chips, 6축 레이더 차트 직접 반영 |
| **menulens.app 실패** | 수익 모델 없음, 경고문 노출이 신뢰 훼손 | blur + 잠금으로 호기심 유도, "여행 패스" 언어 사용 |
| **TransMenu** | 번역 + 환율만, UX 단조로움 | 음식 스토리텔링 레이어 추가로 차별화 |

## 2. 핵심 UX 원칙

### 2.1 즉각적 만족감 (Yuka 학습)
스캔 → 결과 체감 3초 이내. 캐시 히트 시 즉시. 로딩 중 Fun Fact로 체감 대기시간 단축.

### 2.2 카메라가 앱의 전부 (Google Lens 학습)
홈 화면의 유일한 CTA는 카메라 버튼. 다른 요소가 경쟁하지 않음.

### 2.3 카드 기반 정보 설계 (인포그래픽 학습)
음식 하나 = 카드 하나. 맛 프로필 / 재료 / Fun Fact 각각 독립 카드.

### 2.4 자연스러운 페이월 (Yuka + menulens 학습)
무료에서 충분한 가치 → 더 보고 싶을 때 자연스럽게 유도. blur + 잠금 처리.

### 2.5 여행자 언어 (수익 모델 연계)
"구독" 대신 "패스". "7일 여행 패스" 언어가 실제 여행 일정과 심리적으로 일치.

### 2.6 어두운 식당 대응
카메라 플래시 토글 필수. 다크 모드 우선 검토. 밝은 메뉴판 + 어두운 조명 환경 테스트 필요.

## 3. 화면 구조 (5 screens)

```
홈
 └─ 카메라 뷰파인더
      └─ 로딩 (Fun Fact)
           └─ 결과 리스트
                ├─ 음식 상세 카드 (Bottom Sheet)
                └─ 조합 추천
                     └─ Trip Pass 페이월
```

## 4. 화면별 상세 설계

### 4.1 홈 화면

**목적:** 단 하나의 행동 — 스캔 시작

| 요소 | 내용 | 우선순위 |
|---|---|---|
| 카메라 버튼 | 화면 중앙, 대형 원형 버튼 | 필수 |
| 갤러리 버튼 | 카메라 버튼 옆 보조 | 필수 |
| 크레딧 잔량 | 상단 네비게이션에 항상 노출 | 필수 |
| 크레딧 + 패스 카드 | 소진 전부터 자연스럽게 인지 유도 | 필수 |
| 히어로 영역 | 최근 스캔 음식 이미지 표시 | 권장 |
| 최근 스캔 히스토리 | 하단 3개 칩, 오프라인에서도 열람 가능 | 권장 |
| Trip Pass 배너 | 여행 전 유도 | 선택 |

**UX 결정:**
- 크레딧이 소진되기 전부터 잔량이 보여야 패스 구매로 자연스럽게 연결됨
- 히어로 영역은 최근 스캔한 음식 이미지로 채워 앱 사용 동기 부여

---

### 4.2 카메라 화면

**목적:** 메뉴판 촬영 최적화

| 요소 | 내용 | 우선순위 |
|---|---|---|
| 전체 화면 뷰파인더 | 다른 UI 없이 카메라만 | 필수 |
| 코너 가이드 오버레이 | Google Lens 레퍼런스, 촬영 범위 직관적 인지 | 필수 |
| 촬영 버튼 | 하단 중앙, 대형 | 필수 |
| 갤러리 전환 | 하단 좌측 | 필수 |
| 플래시 토글 | 어두운 식당 대응 | 권장 |
| 가이드 텍스트 | "메뉴판을 프레임 안에" | 권장 |

---

### 4.3 로딩 화면

**목적:** 기다림을 콘텐츠로 전환 (Yuka 아이디어)

| 요소 | 내용 | 우선순위 |
|---|---|---|
| 음식 로딩 애니메이션 | 촬영한 음식 프리뷰 | 필수 |
| Fun Fact 카드 | 랜덤 음식 이야기 — 체감 대기시간 단축 | 권장 |
| 예상 시간 | "평균 3초 · 캐시 적중 시 즉시" | 선택 |

**기술 연계:**
- 캐시 히트 시 → 로딩 화면 생략, 즉시 결과로 전환
- 신규 분석 시 → Fun Fact 표시하며 API 응답 대기

---

### 4.4 결과 리스트

**목적:** 메뉴판 전체를 한눈에 스캔 가능하게

| 요소 | 내용 | 우선순위 |
|---|---|---|
| 음식명 (원문 + 번역) | 두 줄 표시 | 필수 |
| 가격 | 스캔된 경우 | 필수 |
| 음식 섬네일 | Google Custom Search API, 없으면 카테고리 색상 폴백 | 필수 |
| 알러지 태그 | 색상 구분 (Yuka 원칙), 리스트에서 즉시 판단 | 필수 |
| 카테고리 필터 | 전체 / 메인 / 사이드 / 음료 | 권장 |
| 조합 추천 버튼 | 하단 고정 바, 항상 접근 가능 | 권장 |

**알러지 태그 색상 체계 (Yuka 학습):**

| 태그 | 색상 | 의미 |
|---|---|---|
| shellfish / 해산물 | 빨강 계열 | 주의 필요 |
| pork / 돼지고기 | 앰버 계열 | 할랄 불가 |
| gluten-free | 초록 계열 | 안전 정보 |
| vegan | 초록 계열 | 안전 정보 |

---

### 4.5 음식 상세 카드

**목적:** 음식 하나를 깊이 이해하는 경험

#### 무료 구간
| 요소 | 내용 |
|---|---|
| 음식 사진 | 상단 히어로 이미지 |
| 번역 3종 | 원문 / 직역 ("부처님이 담을 넘는 요리") / 의역 |
| 핵심 재료 | ingredient chips, 알러지 있는 재료 빨간 강조 |
| 알러지 태그 | 할랄 / 비건 / 채식 뱃지 |
| 가격 등급 | budget / mid / premium |

#### 유료 구간 (잠금 처리)
| 요소 | 잠금 방식 | 가치 |
|---|---|---|
| 맛 레이더 차트 (6축) | blur + 잠금 아이콘 | 직관적 맛 예상 |
| Fun Fact · 이름 유래 | blur + 잠금 아이콘 | 차별화 핵심 |
| 먹는 방법 가이드 | blur + 잠금 아이콘 | 첫 방문자 실질 도움 |
| 조합 추천 연동 | 잠금 아이콘 | 메뉴판 전체 분석 |

**잠금 UX 원칙:**
- 경고문/광고 없이 blur + 잠금 아이콘만으로 처리 (menulens 실패 반면교사)
- 무료에서도 충분한 가치를 느낀 후 유료 유도
- 카드 하단에 Trip Pass CTA 자연스럽게 삽입

---

### 4.6 조합 추천

**목적:** menulens·Google Lens에 없는 핵심 차별화 기능

| 요소 | 내용 |
|---|---|
| 가성비 세트 | 예산 내 최적 조합 |
| 균형 세트 | 영양·맛 균형 조합 |
| 프리미엄 세트 | 가격 제한 없는 최고 조합 |
| 알러지 필터 적용 | 사용자 설정 기반 |
| 총 가격 표시 | 가격 스캔된 경우 |

---

### 4.7 Trip Pass 페이월

**목적:** 구독처럼 느껴지지 않는 자연스러운 전환

| 요소 | 내용 | 우선순위 |
|---|---|---|
| 미리보기 blur 영역 | "아쉬움" 유도 | 권장 |
| Trip Pass 7일 ($2.99) | 시각적 1순위, featured 강조 | 필수 |
| Trip Pass 30일 ($5.99) | 2순위 | 필수 |
| Credits 50회 ($1.99) | 3순위, 부담 없는 진입 | 필수 |
| "여행자 추천" 뱃지 | 7일 패스에만 표시 | 권장 |
| Skip 버튼 | 작게 처리, 강제 없음 | 필수 |

**카피 원칙:**
- "구독" 사용 금지 → "패스" / "여행 기간"
- "더 깊이 탐험하고 싶으신가요?" — 강요 없는 호기심 자극
- "일회성 결제" 명시 — 구독 피로감 제거

## 5. 맛 레이더 차트 스펙

빈대떡 인포그래픽에서 직접 도입한 핵심 컴포넌트.

```
6축 구성:
  감칠맛 (umami)   — 상단
  짠맛   (salty)   — 우상
  단맛   (sweet)   — 우하
  신맛   (sour)    — 좌하
  매운맛 (spicy)   — 좌상
  진함   (rich)    — 중앙 별도 표시 or 6번째 축

점수: 0–5 정수
색상: 코랄 (#D85A30) 반투명 fill
크기: 모바일 기준 120×120px
```

**API 응답 예시:**
```json
"flavor_profile": {
  "sweet": 2,
  "salty": 4,
  "spicy": 1,
  "sour": 1,
  "umami": 5,
  "rich": 5
}
```

## 7. 브랜드 방향 (미확정, 권장안)

### 7.1 컬러 팔레트

| 역할 | 색상 | 헥스 | 근거 |
|---|---|---|---|
| Primary | 코랄 오렌지 | `#D85A30` | 음식의 따뜻함, 식욕 자극 |
| Background | 크림 베이지 | `#FDFAF5` | 자연스러운 음식 톤 |
| Surface | 라이트 베이지 | `#F8F6F2` | 카드 배경 |
| Text Primary | 다크 브라운 | `#2C1A0E` | 따뜻하면서 가독성 |
| Text Secondary | 미디엄 브라운 | `#8B6A50` | 보조 정보 |
| Accent | 앰버 | `#BA7517` | 가격, 강조 정보 |
| Success | 그린 | `#639922` | 안전 알러지, 비건 |
| Danger | 레드 | `#E24B4A` | 주의 알러지 |

### 7.2 타이포그래피 (권장)
- 한국어 / 일본어 / 중국어: `Noto Sans KR / JP / SC`
- 영문 숫자: `Inter` 또는 `DM Sans`
- 음식명 강조: `font-weight: 700`, `letter-spacing: -0.3px`

### 7.3 아이콘 스타일
- 선형 아이콘 (stroke, 1.5px)
- 알러지 뱃지는 채운 pill 형태
- 카메라 UI는 흰색 선형

## 8. 공유 카드 기능 (V2)

빈대떡 인포그래픽 프롬프트 벤치마킹 결과, SNS 공유 카드를 V2 기능으로 확정.

**전략:**
```
기본 카드     → Claude 렌더링 (정확한 정보, 빠름, 저렴)
음식 사진     → Google Custom Search API
SNS 공유 카드 → 인포그래픽 스타일 렌더링 (유료 기능)
```

**공유 카드 구성 요소:**
- 음식 히어로 이미지 (실제 사진)
- 음식명 (원문 + 번역)
- 맛 레이더 미니 차트
- 핵심 재료 3개
- Fun Fact 한 줄
- Transtaste 워터마크 (바이럴 루프)

**바이럴 루프 설계:**
```
사용자 공유 → SNS 노출 → "이게 뭐야?" → 앱 설치 → 무료 10회 체험 → Trip Pass 전환
```

## 9. 반응형 / PWA 고려사항

| 항목 | 내용 |
|---|---|
| 뷰포트 | 모바일 우선 (375px~430px 기준) |
| PWA | manifest.json + service worker, 홈 화면 추가 유도 |
| 카메라 API | `getUserMedia` (PWA), 갤러리는 `<input type="file">` |
| 오프라인 | 최근 스캔 10개 IndexedDB 캐싱 |
| 이미지 압축 | 업로드 전 canvas로 리사이즈 (max 1024px, JPEG 80%) |
| 다크 모드 | 카메라 화면은 항상 다크, 나머지는 시스템 따름 |
