# TransTaste — Claude Chrome QA 리뷰
> 작성일: 2026-03-28 | 출처: Claude Chrome 자동 리뷰 (v0.2.0 기준)

---

## 🔴 심각한 문제 (즉시 수정 필요)

**1. 스캔 히스토리가 전부 같은 URL을 가리킴**

홈의 "Recent Scans" 항목 3개(ผัดไทย, とんこつラーメン, 佛跳墙)가 모두 /results라는 동일한 URL로 연결됩니다. URL에 ID나 쿼리 파라미터가 전혀 없어, 클릭해도 어느 기록이든 동일한 한국 BBQ 결과 화면이 나옵니다. 히스토리 기능이 사실상 작동하지 않습니다.

**2. 카메라 페이지에 뒤로가기 버튼이 없음**

/camera 진입 시 탈출 경로가 전혀 없습니다. 네비게이션 바도 사라지고, 뒤로가기 버튼도 없어 브라우저 버튼을 직접 눌러야만 나올 수 있습니다. 실수로 카메라를 열었을 때 사용자가 갇히는 구조입니다.

**3. "Popular Dishes Nearby" 카드가 클릭 불가**

홈 하단의 Pho Bo, Omakase, Tom Yum, Xiao Long Bao 카드는 시각적으로 클릭 가능한 것처럼 생겼지만 실제로는 아무 반응도 없습니다. 인터랙션이 없는 UI 요소는 사용자 혼란을 유발합니다.

**4. 콤보 추천(Combo Recommendations) 기능이 페이월 뒤에 숨겨진 채 제대로 표시 안 됨**

버튼을 클릭하면 흐릿하게 처리된 콘텐츠와 자물쇠 아이콘만 보이고, 정작 "어떤 콤보인지" 힌트조차 없습니다. 사용자가 무엇을 사는지 알 수 없는 상태에서 결제를 유도하는 구조입니다.

---

## 🟠 중요한 문제 (빠른 개선 필요)

**5. 접근성(Accessibility) 전반적 미흡**

메인 카메라 링크(/camera)가 텍스트도, aria-label도 없는 빈 링크입니다. 내비게이션 바의 카메라 버튼도 동일하게 레이블이 없습니다. 스크린 리더 사용자는 이 버튼의 기능을 알 수 없습니다.

**6. user-scalable=no 설정**

뷰포트 메타 태그에 maximum-scale=1, user-scalable=no가 설정되어 있어 사용자가 화면을 확대할 수 없습니다. 시력이 낮은 사용자의 접근성을 차단하며, WCAG 접근성 지침 위반입니다.

**7. 프리미엄 페이월 타이밍이 너무 이름**

10회 무료 스캔이 주어지지만, 결과 페이지에서 dish 하나를 클릭하면 즉시 결제 유도 화면이 등장합니다. "flavor profile", "fun facts" 같은 부가 정보를 위해 $2.99를 내야 하는데, 이 정보의 가치를 먼저 맛볼 기회가 전혀 없습니다. 첫 1~2회는 전체 콘텐츠를 무료로 보여주는 방식이 전환율에 훨씬 유리합니다.

**8. 결제 플랜 구조의 비일관성**

결제 옵션이 "7-Day Pass $2.99", "30-Day Pass $5.99", "50 Credits $1.99" 3가지인데, 개당 단가 계산 시 Credits가 가장 저렴합니다. 이를 첫 번째로 추천하는 "Traveler Pick"은 7-Day Pass인데, 명확한 가격 비교 정보 없이 사용자를 더 비싼 옵션으로 유도하는 구조입니다.

**9. H1~H3 헤딩 계층 구조가 의미론적으로 잘못됨**

홈 페이지에서 "TransTaste" 로고가 h1, 메인 슬로건이 h2, "Recent Scans"와 "Popular Dishes Nearby"가 h3으로 설정되어 있습니다. 로고는 헤딩이 아니라 링크 또는 브랜딩 요소여야 하며, 실제 핵심 슬로건이 H1이 되어야 합니다.

## 🟡 개선하면 좋을 사항 (중장기 과제)

**10. "Order" 기능이 독립적으로 작동하지 않음**

/order 페이지 진입 시 "No items yet – Scan a menu to start ordering"만 표시됩니다. 스캔 결과에서 + 버튼을 눌러도 실제로 주문 목록에 반영되는지 확인이 안 됩니다.

**11. 지원 언어 불일관성**

UI 언어 설정은 8개 언어(영어·한국어·일본어·중국어·태국어·베트남어·스페인어·프랑스어)를 지원하지만, Phrases 기능은 5개(일본어·중국어·태국어·베트남어·영어)만 지원합니다. 한국어·스페인어·프랑스어 사용자는 회화 기능을 쓸 수 없습니다.

**12. OG 이미지가 없음**

og:image 태그가 누락되어 있어, SNS 공유 시 이미지 없이 텍스트만 표시됩니다.

**13. 개별 페이지의 메타 타이틀이 모두 동일**

프로필, 결과, 히스토리 등 모든 페이지의 title이 "TransTaste — Travel Menu Translator"로 동일합니다.

**14. "Travel Tip" 섹션이 고정 텍스트**

Travel 페이지 하단의 "Travel Tip" 카드가 "호텔 주소 사진 찍어두기"라는 단일 고정 문구입니다.

**15. 히스토리 기록 삭제 기능 없음**

/history 페이지에 스캔 기록이 쌓이지만 삭제하거나 관리할 방법이 없습니다.

## UX 여정 분석 (첫 사용자 관점)
> 출처: Claude Chrome UX 여정 분석 (동일 세션)

### 여행 전 준비 단계

| 단계 | 평가 | 핵심 이슈 |
|---|---|---|
| ① 온보딩 1단계 | ✅ 좋음 | 스와이프 무반응 (소 이슈) |
| ② 온보딩 2단계 | 🔴 문제 | "Skip for now" 버튼이 BottomNav에 완전히 가려짐 |
| ③ 홈 화면 | ✅ 좋음 | Popular Dishes 클릭 불가 (기존 이슈) |
| ④ Travel Tools | 🟡 아쉬움 | Quick Phrase 클릭 시 페이지 전환 (인라인이 자연스러움) |
| ⑤ Phrases | ✅ 좋음 | 북마크 저장 후 확인 경로 없음 |

### 식당 현장 단계

| 단계 | 평가 | 핵심 이슈 |
|---|---|---|
| ⑥ 카메라 실행 | 🔴 심각 | 뒤로가기 없음 — 기존 이슈, 재확인 |
| ⑦ 스캔 결과 목록 | ✅ 좋음 | 카테고리 필터 유용 |
| ⑧ 음식 상세 | 🔴 심각 | 페이월 힌트 없음 — 기존 이슈, 재확인 |
| ⑨ 주문 담기 | ✅ 좋음 | Added ✓ 피드백 명확 |
| ⑩ Show to Server | ✅ 최고 | Confirmed 후 주문 초기화 안 됨 |
| ⑪ Order with Phrases | ✅ 좋음 | 연결 흐름 자연스러움 |

### 3대 이탈 포인트

```
1. 카메라 탈출 경로 없음 (⑥)
   → 특히 기술 비숙련 여행자에게 심각

2. 페이월 힌트 없음 (⑧)
   → 무엇을 사는지 모르고 결제 불가

3. Skip for now 버튼 가려짐 (②)
   → 설정 강제처럼 느껴짐
```

### 최고 경험 구간

```
결과 목록 → 주문 담기 → Show to Server
→ 실제 식당 상황에서 빠르고 직관적
→ 이 구간이 핵심 가치 전달 포인트
```

### UX 여정 분석 (원문)

#### 📱 여행 전 준비 단계

**① 앱 첫 실행 — 온보딩 1단계**

처음 열면 3가지 핵심 기능이 아이콘+설명으로 소개됩니다. 군더더기 없이 깔끔하고 "10 free scans included"라는 문구가 부담 없이 시작하게 유도합니다. 좋은 첫인상입니다. 다만 스와이프로 넘길 수 없고 반드시 "Get Started" 버튼을 눌러야 다음 단계로 갑니다. 상단의 페이지 인디케이터(●○)가 있어 2단계짜리 온보딩임을 알 수 있지만, 첫 화면에서 스와이프를 시도하면 반응이 없어 잠깐 당황할 수 있습니다.

**② 온보딩 2단계 — 언어·알레르기 설정**

언어 선택과 알레르기 설정, 식단 선호도가 한 페이지에 다 담겨 있습니다. 스크롤을 내려야 전체가 보이는데, **"Skip for now" 버튼이 하단 네비게이션 바에 완전히 가려져 있어 사실상 보이지 않습니다.** 직접 코드로 확인하니 버튼 자체는 존재하지만 네비게이션 바 뒤에 숨겨진 상태입니다. 스킵을 원하는 사용자는 방법을 찾지 못할 가능성이 높습니다.

**③ 홈 화면 진입**

설정 완료 후 메인 화면으로 넘어옵니다. 카메라 버튼이 화면 중앙에 크게 있고, 아래에 Gallery / URL / Text 보조 입력 수단도 보입니다. 전체적으로 "뭘 해야 하는지" 명확하게 전달됩니다. 스크롤하면 최근 스캔 기록, Travel Tools 배너, 인기 음식 카드가 있습니다. 다만 인기 음식 카드(Pho Bo, Tom Yum 등)는 클릭해도 아무 반응이 없어, 콘텐츠인지 버튼인지 알 수 없습니다.

**④ Travel Tools 미리 살펴보기**

여행 전 준비하는 사람이라면 Travel 탭을 먼저 탐색할 것입니다. 탭 진입 시 "Water, please / Check, please / No spicy" 등의 빠른 구문 버튼이 맨 위에 있어 즉시 유용합니다. 그런데 이 버튼을 누르면 곧바로 Phrases 페이지로 이동해버립니다. Travel 페이지 자체에서 팝업이나 인라인으로 보여주는 것이 자연스러울 텐데, 페이지 전환이 일어나서 약간 이동 감각을 잃습니다.

**⑤ Phrases 미리 익히기**

일본어/중국어/태국어 등 언어별, Basics/Ordering/Payment/Issues 카테고리별로 잘 구성되어 있습니다. "Server might say" 섹션이 특히 유용합니다. 서버가 뭐라고 대답할지 미리 알 수 있어 실제 대화 준비에 도움이 됩니다. 다만 북마크 버튼(☆)이 있는데 저장된 북마크를 어디서 다시 볼 수 있는지 경로가 전혀 표시되지 않습니다.

#### 🍽️ 식당 현장 단계

**⑥ 카메라 실행 — 가장 큰 충격 포인트**

식당에 도착해 카메라 버튼을 누르면 화면 전체가 새까만 카메라 뷰로 바뀝니다. 네비게이션 바가 완전히 사라지고, **뒤로가기 버튼도 없습니다.** 실수로 카메라를 열었거나 마음이 바뀐 경우 브라우저 뒤로가기 제스처를 써야만 빠져나올 수 있는데, 이것을 모르는 사용자는 당황할 수 있습니다. 특히 나이가 있는 사용자나 기술에 익숙하지 않은 여행자에게 심각한 진입장벽입니다.

**⑦ 스캔 결과 — 메뉴 목록 화면**

스캔이 완료되면 메뉴 항목들이 카드 형태로 나열됩니다. 원어 이름과 영어 번역, 가격이 한 눈에 보입니다. 카테고리 필터(Main/Soup/Noodle 등)도 상단에 있어 메뉴가 많을 때 유용합니다. 여기까지는 매우 좋은 경험입니다.

**⑧ 음식 상세 클릭 — 페이월 등장**

메뉴 항목을 클릭하면 음식 이름, 뜻, 가격, 카테고리 정도는 무료로 볼 수 있습니다. 그런데 "ALLERGENS & DIETARY" 섹션 바로 아래부터 내용이 비어있고, 스크롤하면 맛 프로파일, 재료 정보가 모두 흐릿하게 처리된 채 자물쇠 아이콘이 나타납니다. **"무엇을 잠금해제 하는 건지" 힌트가 전혀 없습니다.** 흐릿하게 처리된 텍스트 내용이 무엇인지 전혀 알 수 없어, 가격을 낼 만한 가치인지 판단이 불가능합니다.

**⑨ 주문 담기 → Order 탭**

음식 상세 화면 맨 아래 "Add to Order" 버튼을 누르면 "Added ✓"로 바뀌며 시각적 피드백이 즉시 나타납니다. 좋은 경험입니다. Order 탭으로 가보면 담은 음식 목록, 수량 조절(−/+), 소계·합계가 명확하게 표시됩니다.

**⑩ Show to Server — 가장 좋은 순간**

"Show to Server →" 버튼을 누르면 화면이 완전히 바뀌어 원어 음식명과 수량, 가격만 크게 표시됩니다. 서버에게 폰 화면을 보여주는 용도로 디자인된 것입니다. 직관적이고 실용적입니다. 다만 "Confirmed" 버튼을 눌러 돌아오면 **주문 목록이 초기화되지 않습니다.** 주문이 완료됐는지, 아직 진행 중인지 상태가 불분명합니다.

**⑪ Order with Phrases**

Order 페이지 하단 "Order with phrases" 링크를 누르면 Phrases의 Ordering 탭으로 이동합니다. 연결 자체는 좋은 아이디어입니다. 주문서를 보여주고 추가로 "Is this spicy?" 같은 확인 표현을 바로 쓸 수 있는 흐름이 자연스럽습니다.

#### 전체 여정 요약 평가

흐름 단계에서 가장 매끄러운 구간은 **결과 목록 → 주문 담기 → Show to Server** 구간으로, 실제 식당 상황에서 빠르게 쓸 수 있도록 잘 설계되어 있습니다. 반면 가장 큰 마찰 지점은 세 곳입니다. 카메라 화면에서 탈출 경로가 없는 것, 상세 화면에서 무엇이 잠겨 있는지 보여주지 않고 결제를 요구하는 것, 그리고 온보딩의 "Skip for now" 버튼이 네비게이션 바에 가려져 숨겨진 것입니다. 이 세 가지는 모두 사용자가 앱을 이탈하게 만드는 직접적인 원인이 될 수 있습니다.

## 추가 관점 리포트 (원문 보존)
> 출처: Claude Chrome 심층 분석 — 코드·데이터 기반 추가 발견

### 1. 비즈니스 생존가능성 — 수익 모델이 쉽게 우회됨

스캔 10회 무료 제한이 서버가 아니라 클라이언트 기반으로 관리될 가능성이 높습니다. `localStorage`에 스캔 카운트 키가 없고, `sessionStorage`와 `IndexedDB`도 비어 있습니다. 이는 시크릿 모드로 열거나 브라우저 데이터를 지우면 10회가 리셋될 수 있다는 뜻입니다. 결제 없이 반영구적으로 쓸 수 있는 구조라면 비즈니스 모델 자체가 흔들립니다. 사용자 계정 시스템이 없는 것도 이 문제와 직결됩니다. 계정이 없으니 디바이스 간 이동, 기기 변경 시 구매 내역 복구, 사용 이력 연속성이 전혀 없습니다.

### 2. 국제화(i18n)가 반만 됨

UI 언어를 한국어로 설정하면 네비게이션 바("홈/여행/기록/프로필"), 메인 슬로건, 카테고리 필터 등 일부 UI 요소는 한국어로 바뀝니다. 하지만 "RECENT SCANS" 섹션 타이틀, Tip & Culture 본문 설명, 역사 페이지 타임스탬프("2h ago / Yesterday")는 그대로 영어입니다. 일부는 번역되고 일부는 안 되는 앱은 어느 언어 사용자에게도 어색하게 느껴집니다. 한국어를 모국어로 설정한 사용자가 "2h ago"를 보면 설정이 제대로 된 건지 의심하게 됩니다.

### 3. 오프라인 대응이 전혀 없음 — 여행 앱의 치명적 약점

PWA Manifest는 설정되어 있고 `display: standalone`으로 앱처럼 설치도 가능하지만, Service Worker가 없고 Cache Storage가 완전히 비어 있습니다. 즉 인터넷이 끊기면 앱 자체가 열리지 않습니다. 여행자는 식당 안에서 와이파이가 약하거나, 데이터 로밍이 안 되거나, 비행기 모드인 상황이 흔합니다. Phrases나 Tip & Culture 같은 정적 콘텐츠는 미리 캐시해두면 충분히 오프라인 제공이 가능한데, 이 기능이 전무합니다. "여행 앱"이라는 카테고리에서 오프라인 미지원은 핵심 경쟁력 결함입니다.

### 4. 경쟁사 대비 포지셔닝이 불분명

Google Translate는 이미 카메라로 메뉴를 실시간 번역하고, 100개 이상 언어를 무료로 지원합니다. TransTaste가 내세우는 차별점은 알레르기 감지, 서버와의 소통 구문, 팁 문화 가이드인데, 이 중 가장 핵심인 알레르기 감지는 페이월 뒤에 있고 정작 무료 구간에서는 번역 외에 Google Translate 대비 뚜렷한 우위가 보이지 않습니다. 온보딩에서 "왜 Google Translate 대신 이 앱을 써야 하는가"를 설득하는 내용이 없습니다.

### 5. 신뢰와 안전 — 알레르기 기능의 역설

앱의 핵심 가치 중 하나가 알레르기 보호인데, 이를 가장 필요로 하는 사람(알레르기가 심각한 사용자)에게 가장 큰 리스크가 있습니다. 알레르기 정보가 AI 생성이라는 면책 문구는 법적으로는 올바르지만, 사용자가 이 정보를 실제 안전 근거로 삼을 가능성이 높습니다. Privacy Policy에는 "알레르기 데이터를 스캔 시 Anthropic에 전송한다"고 명시되어 있는데, 이 사실이 온보딩이나 알레르기 설정 화면에서 전혀 고지되지 않습니다. GDPR/개인정보 관점에서 민감 정보(건강 데이터) 처리에 대한 명시적 동의 절차가 없는 것은 법적 리스크입니다.

### 6. 콘텐츠 커버리지와 성장 전략

Tip & Culture 가이드는 20개국을 지원하는데, 직접 확인한 결과 대만, 홍콩, 필리핀, 캄보디아, 모로코, UAE, 브라질, 페루 등 실제로 음식 문화가 생소한 주요 여행지들이 빠져 있습니다. Phrases 기능도 5개 언어만 지원해, 예를 들어 한국어 사용자가 스페인 식당에서 쓸 수 있는 회화 지원이 없습니다. 또한 이 앱이 어떻게 신규 사용자를 획득할지에 대한 전략이 보이지 않습니다. `robots: noindex`라 검색 유입이 없고, 소셜 공유 기능(결과 공유, 친구에게 추천 등)도 없으며, OG 이미지도 없습니다. 사용자가 앱을 쓰다가 자연스럽게 주변에 퍼뜨리는 바이럴 루프가 전혀 설계되어 있지 않습니다.

## FAQ 분석 리포트 (원문 보존)
> 출처: Claude Chrome — 신규 사용자 FAQ 필요 구간 분석

### FAQ가 절실했던 구간들

**📍 온보딩 단계**

"알레르기 정보는 얼마나 믿을 수 있나요?"
온보딩에서 알레르기를 설정하라고 하는데, 정작 이 정보의 정확도나 한계에 대한 설명이 없습니다. "AI가 생성한 정보이며 의학적 근거가 아닙니다"라는 면책 문구가 작은 글씨로 있지만, 사용자가 왜 설정해야 하는지, 설정하면 어떻게 작동하는지에 대한 기대치 설정이 전혀 없습니다.

"스킵하면 나중에 다시 설정할 수 있나요?"
"Skip for now" 버튼이 숨겨져 있어서 존재조차 모르는 사용자가 많겠지만, 발견했더라도 "나중에 어디서 다시 설정하지?"라는 의문이 생깁니다. 프로필 탭에 가면 수정 가능하다는 안내가 어디에도 없습니다.

**📍 홈 화면**

"10 scans left가 뭔가요? 다 쓰면 어떻게 되나요?"
우상단의 "⚡ 10 scans left"가 처음 보는 사람에게는 생소합니다. 스캔 1회가 정확히 무엇을 의미하는지, 다 소진되면 앱이 멈추는지, 얼마에 더 살 수 있는지가 전혀 설명되어 있지 않습니다.

"인기 음식 카드는 뭐하는 건가요?"
Pho Bo, Tom Yum 같은 카드가 있는데 클릭해도 반응이 없습니다. 눌리는 것처럼 생겼는데 아무 일도 안 일어나서, 앱이 고장 난 건지 내가 뭔가 잘못하는 건지 모르게 됩니다.

**📍 카메라 / 스캔 화면**

"메뉴 전체를 한 번에 찍어야 하나요, 한 페이지씩 찍어야 하나요?"
카메라 화면에 "Place the menu within the frame"이라고만 나옵니다. 긴 메뉴판을 어떻게 스캔해야 하는지, 여러 장 찍을 수 있는지, 흐릿하게 찍히면 어떻게 되는지에 대한 가이드가 전혀 없습니다.

"갤러리, URL, 텍스트 — 어떤 걸 써야 하나요?"
세 가지 입력 방식이 있는데 차이점이 설명되지 않습니다.

**📍 스캔 결과 화면**

"+ 버튼을 누르면 뭐가 되나요?"
각 메뉴 항목 옆의 + 버튼이 있는데, 장바구니 개념인지 단순 즐겨찾기인지 불분명합니다.

"카테고리 필터(Main/Soup/Noodle)는 AI가 분류한 건가요?"
카테고리 태그가 자동 분류된 것임을 모르는 사용자는 이 분류가 얼마나 정확한지 모릅니다.

**📍 음식 상세 / 페이월 구간**

"흐릿하게 처리된 부분이 무엇인가요?"
자물쇠 아이콘 뒤에 무언가 있다는 건 알겠는데, 정확히 어떤 정보가 숨겨져 있는지 힌트가 없습니다.

"7-Day Trip Pass vs 50 Credits — 나한테 어느 게 맞나요?"
결제 옵션이 3가지인데, 어느 걸 골라야 하는지 기준이 없습니다.

**📍 Travel Tools / Phrases**

"언어를 선택했는데, 내가 모르는 언어로 나오면 어떻게 서버한테 보여주나요?"
Phrases에서 일본어로 "水をください"가 나오는데, 사용자가 이걸 읽을 수 없으면 어떻게 하는지 안내가 없습니다.

"즐겨찾기(☆)에 저장한 구문은 어디서 보나요?"
각 구문에 북마크 버튼이 있는데, 저장된 목록을 볼 수 있는 화면이 없습니다.

**📍 주문(Order) / Confirmed 이후**

"Confirmed를 눌렀는데 주문이 된 건가요?"
주문이 완료된 건지, 아직 서버에게 안 보여준 건지, 목록을 비워야 하는지 상태가 전혀 안내되지 않습니다.

### 사용자가 FAQ를 찾으러 열어보는 곳 (실측)

앱 전체에 FAQ, 도움말, 물음표 아이콘, 툴팁이 단 하나도 없음.
/faq, /help, /about 페이지 모두 404.

① "10 scans left" 배지 클릭 → 아무 반응 없음
② 프로필 탭 하단 → Terms/Privacy만 있음, Help 없음
③ 알레르기 면책 문구 클릭 → 정적 텍스트, 반응 없음
④ 페이월 주변 탐색 → 설명 없음
⑤ 북마크 별(☆) 클릭 후 → 저장 목록 확인 방법 없음
⑥ "Show to Server" / "Confirmed" 버튼 근처 → 설명 없음

### FAQ 배치 전략 (원문 결론)

FAQ를 별도 페이지 하나로 몰아두는 것보다, 각 화면 맥락에 맞는 인라인 마이크로 FAQ 방식이 이 앱에 더 적합합니다. 사용자가 막히는 순간이 모두 다른 화면이고, 여행 중 폰을 들고 쓰는 상황이라 FAQ 페이지를 찾아 이동하는 여유가 없기 때문입니다. 다만 프로필 하단에 /faq 페이지는 별도로 두고, 각 화면의 ⓘ / 툴팁 / 인라인 설명들이 거기로 연결되도록 구조를 잡는 것이 이상적입니다.
