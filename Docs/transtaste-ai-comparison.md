# Transtaste — AI 모델 비교 리포트
> 작성일: 2026-03-27 | 목적: 서비스 요구사항 기반 모델 선택 근거 정리

---

## 개요

현재 Claude Sonnet 4.5 단일 모델로 시작. 이 문서는 추후 모델 교체 / 혼합 사용 결정을 위한 기반 지식 정리.
실제 최종 판단은 동일 테스트셋 기반 사람 검수 필요.

## 5. 권장 전략: 역할별 모델 분리

단일 모델보다 입력 타입에 따라 모델을 분리하는 것이 비용/품질 균형에 유리.

### 현재 (MVP)
```
모든 입력 → Claude Sonnet 4.5
```

### V2 권장 (모델 라우팅)
```
이미지 입력  → Claude Sonnet 4.5   (Vision 필수, 품질 우선)
URL 입력     → Claude Sonnet 4.5   (이미지 fetch 포함)
텍스트 입력  → Claude Haiku 4.5    (OCR 불필요, 60~70% 절감)
캐시 히트    → Redis 반환           ($0, 모델 불필요)
```

### V3 검토 (실테스트 후 결정)
```
이미지 입력 (고빈도) → Gemini 2.5 Flash (저비용 옵션, 품질 검증 후)
이미지 입력 (고품질 요구) → Claude Sonnet 4.5
텍스트 입력 → Claude Haiku 4.5
```

## 7. 확장성 설계 — AI Provider 추상화

나중에 모델을 바꾸거나 추가할 때를 대비해 Provider 인터페이스를 추상화.

```typescript
// src/lib/ai/provider.ts

interface AIProvider {
  name: string
  analyzeMenu(input: MenuInput): Promise<MenuAnalysisResult>
  estimateCost(inputTokens: number, outputTokens: number): number
}

class ClaudeProvider implements AIProvider {
  name = 'anthropic'
  // ...
}

class GeminiProvider implements AIProvider {
  name = 'google'
  // ...
}

// 라우터: 입력 타입 + 실험 플래그에 따라 provider 선택
export function selectProvider(inputType: InputType, userId?: string): AIProvider {
  // A/B 테스트나 점진적 전환 시 여기서 제어
  if (inputType === 'text') return claudeHaikuProvider
  return claudeSonnetProvider  // 기본
}
```

이 구조면 Gemini 테스트를 추가하거나 특정 사용자에게만 실험 모델을 적용하는 것이 코드 변경 없이 가능.

## 8. 결론 및 단계별 실행 계획

| 단계 | 기간 | 모델 전략 | 목표 |
