# Transtaste — i18n 전략 & 지원 범위 설계
> 작성일: 2026-03-28 | 버전: v0.1

---

## 1. i18n의 중요성 — 왜 어설프면 안 되는가

번역 앱에서 UI가 반만 번역되면 신뢰도가 치명적으로 무너진다.

```
사용자 경험:
  한국어 설정 → 네비게이션 바는 한국어
  → "RECENT SCANS"는 영어
  → "2h ago"는 영어

사용자 반응:
  "설정이 제대로 된 건가?"
  "이 앱이 한국어를 제대로 지원하는 건 맞나?"
  → 신뢰 저하 → 이탈

역설:
  번역 앱인데 자기 UI를 번역 못 하면
  Google Translate를 쓰는 게 낫다는 결론이 나옴
```

---

## 2. 현재 i18n 상태 감사

### 번역된 것
```
✅ 네비게이션 바 (홈/여행/기록/프로필)
✅ 메인 슬로건
✅ 카테고리 필터 (Main/Soup 등)
✅ 온보딩 텍스트
```

### 번역 안 된 것 (즉시 수정 필요)
```
❌ "RECENT SCANS" 섹션 타이틀
❌ "2h ago / Yesterday" 타임스탬프
❌ Tip & Culture 본문 설명 (일부)
❌ 에러 메시지 일부
❌ 페이월 문구 일부
```

### 구조적 문제
```
UI 언어 지원: 8개 (영어/한국어/일본어/중국어/태국어/베트남어/스페인어/프랑스어)
회화 기능 지원: 5개 (영어/일본어/중국어/태국어/베트남어)
→ 한국어/스페인어/프랑스어 UI 사용자에게 회화 기능 없음
→ 단기: UI 언어를 5개로 줄이거나 / 중기: 회화를 8개로 맞추거나
```

## 3. i18n 키 관리 전략

### 3.1 권장 구조

```
/locales
  /ko          한국어
    common.json      공통 UI
    scan.json        스캔 관련
    travel.json      Travel Tools
    paywall.json     결제 문구
    errors.json      에러 메시지
  /ja          일본어
  /zh          중국어 (간체)
  /zh-TW       중국어 (번체) — 대만 별도
  /th          태국어
  /vi          베트남어
  /en          영어 (기본값/폴백)
```

### 3.2 키 네이밍 원칙

```
나쁜 예:
  "recent_scans"  → 맥락 없음
  "btn1"          → 의미 없음

좋은 예:
  "home.recentScans.title"
  "scan.result.noItems"
  "paywall.phase2.unlockHint"
  "travel.phrases.serverMightSay"

원칙:
  [화면].[섹션].[요소] 3단계
  영어 기본값 필수 (폴백)
  동적 값은 {변수명} 형식
```

### 3.3 번역 누락 방지

```
개발 단계:
  하드코딩 문자열 ESLint 규칙으로 차단
  (i18n-ally VSCode 플러그인 권장)

QA 단계:
  언어별 스크린샷 자동화 (Playwright)
  폴백 영어 표시 시 경고 로그

배포 단계:
  번역 키 커버리지 리포트
  누락 키 = 빌드 실패 처리 가능
```

### 3.4 동적 콘텐츠 처리

```
Claude API 응답 (음식 설명, Fun Fact 등):
  → output_language 파라미터로 언어 지정
  → API가 직접 해당 언어로 생성
  → i18n 키 불필요

정적 콘텐츠 (팁 가이드, 회화집):
  → JSON 파일로 언어별 관리
  → 번역가 또는 Claude로 초벌 후 검수

타임스탬프:
  → Intl.RelativeTimeFormat 사용
  → 언어 설정 자동 반영
  → "2h ago" → "2시간 전" / "2時間前"
```

## 5. 식이 신념별 여행자 규모 & 중요도

### 5.1 무슬림 (할랄) — 최우선 대응

2025년 기준 국제 무슬림 여행자는 2024년 1억 7,600만 명으로 전년 대비 25% 증가했고, 2030년에는 2억 4,500만 명까지 성장할 전망이에요.

```
핵심 아웃바운드 국가 (무슬림):
  인도네시아   2억 7천만 인구 중 87% 무슬림
  말레이시아   3,400만 중 63% 무슬림
  파키스탄     2억 3천만 거의 전부 무슬림
  방글라데시   1억 7천만 중 91% 무슬림
  인도         2억 무슬림 (전체의 14%)
  중동 전체    UAE/사우디/터키 등 여행 활발

핵심 여행 목적지:
  일본, 태국, 싱가포르, 대만, 한국 → 할랄 정보 수요 높음

Transtaste 대응:
  할랄 인증 여부 → main 알러지 수준 처리
  돼지고기 감지 → 항상 경고
  알코올 포함 요리 → 경고
  할랄 대안 추천 → 동일 메뉴판 내
```

### 5.2 힌두교 (소고기 금기) — 중요

```
규모:
  인도 11억 힌두교 신자
  인도 아웃바운드 2024 역대 최고
  네팔, 발리(인도네시아 일부)

Transtaste 대응:
  소고기 포함 메뉴 → 경고
  비프 기반 육수 → 특히 주의 (라멘 등)
  대안: 닭/양/채식 메뉴 추천
```

### 5.3 채식/비건 — 성장 중

```
규모:
  서양권 전반 급증
  인도 채식주의자 (전체 20~30%)
  한국/일본 채식 여행자 증가

복잡도:
  비건 vs 채식 vs 페스코 vs 플렉시테리언
  숨겨진 동물성 재료 (젤라틴, 닭육수 등)

Transtaste 대응:
  동물성 재료 감지 상세화
  "채식처럼 보이지만 아닌 것" 경고
```

### 5.4 코셔 (유대교) — 소규모

```
규모: 전 세계 1,500만 유대인, 여행자 수 적음
복잡도: 코셔 인증이 없으면 판단 어려움
→ 현재: "코셔 인증 식당인지 확인 권장" 메시지로 소프트 커버
```

### 5.5 기타 종교/문화 금기

```
불교 (일부 종파): 육류 금기, 오신채 금기
  → 한국/일본 불교 여행자

글루텐 프리: 셀리악병 의료 이슈 + 선택적 글루텐 회피
  → 서양권 여행자 수요 높음

술 금기: 무슬림 외에도 임산부, 회복 중 알코올중독자 등
```

## 7. i18n 로드맵

### Phase 1 — 즉시 (버그 수준)
```
현재 미번역 하드코딩 문자열 전부 i18n 키로 교체
  "RECENT SCANS" → home.recentScans.title
  "2h ago" → Intl.RelativeTimeFormat 적용
  타임스탬프 전체 자동화
```

### Phase 2 — V1.5 (출시 후)
```
UI 언어 ↔ 회화 언어 정합성 맞추기
  방향 A: UI 언어 5개로 줄이기
  방향 B: 회화 언어 8개로 늘리기 (권장)

팁 가이드 20개국 → 30개국 확장
  대만/홍콩/인도/필리핀/UAE/터키 추가
```

### Phase 3 — V2 (스케일업)
```
회화 언어 아랍어/힌디어 추가
팁 가이드 50개국
할랄 특화 필터 고도화
```

## 8. 요약 — Transtaste i18n 원칙

```
1. 번역 앱이 자기 UI를 반만 번역하면 신뢰 0
   → 현재 미번역 문자열 전수 조사 후 즉시 수정

2. i18n 키는 화면.섹션.요소 3단계로
   → 하드코딩 금지, 영어 폴백 필수

3. Claude API 응답은 output_language로 처리
   → 별도 번역 불필요

4. 무슬림 여행자 = 무시할 수 없는 규모
   → 할랄 필터를 핵심 기능으로 대우

5. 대만/홍콩은 중국어지만 번체 별도 처리
   → zh ≠ zh-TW, 같이 쓰면 안 됨
```
