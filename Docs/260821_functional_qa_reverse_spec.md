## 2. 역기획한 제품 정의

### 핵심 사용자

외국 식당에서 메뉴 언어를 읽기 어렵고 채식, 종교식, 알레르기 또는 기피 재료 조건을 가진 여행자.

### 핵심 문제

단순 번역만으로는 무엇을 피해야 하는지, 무엇을 직원에게 확인해야 하는지, 실제로 어떻게 주문할지 결정하기 어렵다.

### 핵심 가치

메뉴 입력을 `피하기 / 직원 확인 / 명시된 우려 없음`의 의사결정 정보로 바꾸고, 선택한 요리를 현지어 주문 화면까지 연결한다.

### 핵심 성공 여정

```text
홈
→ 카메라·갤러리·URL·텍스트·샘플 메뉴 입력
→ 이번 스캔에 적용할 제한식·기피 재료 선택
→ 메뉴 분석
→ 위험도별 결과와 근거 확인
→ 요리 상세 확인 및 주문 추가
→ 주문 수량·가격·주의 항목 검토
→ 현지어 직원 제시 화면
→ 주문 확인
→ 기록 저장 또는 다음 스캔
```

## 3. 기능 영역과 현재 계약

| 영역 | 사용자 계약 | 상태·데이터 |
|---|---|---|
| 입력 | 카메라, 갤러리, URL, 텍스트, 샘플 메뉴를 지원 | 입력은 `sessionStorage`의 `scanInputType`, `scanImage`, `scanText`에 임시 저장 |
| 빠른 설정 | 분석 전에 채식·비건·할랄과 기피 재료를 선택 | `transtaste_user_settings`에 snake_case로 저장 |
| 분석 | 입력과 설정을 `/api/analyze`로 보내 결과 또는 명시적 오류를 받음 | 성공 시에만 크레딧 차감, 실제 실패를 샘플로 대체하면 안 됨 |
| 결과 | 위험도, 근거, 번역, 가격, 상세, 주문 추가 제공 | 결과는 sessionStorage에서 소비한 뒤 localStorage 기록·캐시에 저장 |
| 상세 | 선택한 요리만 `/api/analyze/detail`로 지연 요청 | Phase 2 데이터와 오류·재시도 상태 제공 |
| 주문 | 선택 요리, 수량, 합계, 확인 필요 항목 제공 | 카트는 탭 단위 `sessionStorage` 유지 |
| 직원 제시 | 원문 요리명·수량·제한식 문장을 고대비로 표시 | Wake Lock을 시도하고 AI 참고 정보 면책을 표시 |
| 기록 | 과거 분석 결과를 다시 열고 개별·전체 삭제 | 현재는 기기 localStorage 전용 |
| 가격 검증 | 결제 대신 3·7·30일 패스 관심을 측정 | 7일 추천, 이벤트는 로컬 저장. 실제 Stripe는 HOLD |
| 계정·동기화 | 첫 분석은 익명, 향후 선택 가입 | Supabase Auth와 서버 동기화는 HOLD |

## 4. 핵심 인수 기준

### F1. 입력과 분석 준비

- 샘플 메뉴 CTA는 `/scan-setup`으로 이동한다.
- 제한식과 기피 재료 선택은 저장 후 분석 요청에 포함된다.
- 입력이 없으면 분석을 시작하지 않고 복구 가능한 오류를 제공한다.

### F2. 분석 API 안전 경계

- 입력 누락은 `400 E_BAD_REQUEST`를 반환한다.
- 데모 환경은 반드시 `demo: true`인 고정 데이터를 반환하고 외부 AI를 호출하지 않는다.
- 실제 AI가 비활성 또는 미설정이면 `503 E_SERVICE_UNAVAILABLE`을 반환한다.
- 실패 시 샘플 결과로 자동 대체하지 않는다.
- 성공한 실제 분석에서만 크레딧을 차감한다. 샘플은 무료량과 분리한다는 D15 정책을 따라야 한다.

### F3. 결과와 주문

- 결과는 현재 제한식 기준과 위험도 근거를 보여준다.
- 데모 결과는 화면에서 예시 데이터임을 명확히 표시한다.
- 요리를 주문에 추가하면 `/order`에서 동일 요리와 수량을 볼 수 있다.
- 위험 또는 불확실 요리는 주문 화면에서 다시 직원 확인을 요구한다.

### F4. 직원 제시

- 직원 제시 화면은 메뉴 언어의 주문명과 수량을 우선 표시한다.
- 선택한 알레르기·제한식 문장을 함께 표시한다.
- AI 결과가 보장 정보가 아니라는 짧은 경고를 표시한다.
- 확인 완료 후 주문 화면으로 돌아오고 완료 상태를 알려준다.

### F5. 기록과 수익 검증

- 성공 결과는 스캔 단위 하나로 기록·캐시된다.
- 기록에서 같은 결과를 다시 열 수 있고 삭제할 수 있다.
- 7일 패스 관심 행동은 `experiment`, `plan`, `days`, `price`와 함께 기록된다.
- 실제 결제나 권한은 Stripe webhook 기반 서버 entitlement 전에는 부여하지 않는다.

## 5. 2026-08-21 기능 QA 결과

### 검증한 사용자 스토리

사용자가 샘플 메뉴를 선택하고 비건·기피 재료를 설정한 뒤, 데모 분석 결과에서 요리를 주문에 담아 직원 제시 화면까지 완료한다.

### 경계별 결과

| 경계 | 판정 | 증거 |
|---|---|---|
| 홈 → 빠른 설정 | PASS | 샘플 메뉴 CTA가 `/scan-setup`으로 이동 |
| 빠른 설정 저장 | PASS | `dietary_beliefs: ["vegan"]`, `disliked_ingredients: ["peanut"]` 저장 확인 |
| 잘못된 요청 → 분석 API | PASS | 입력 없는 POST가 `400 E_BAD_REQUEST` 반환 |
| 데모 분석 요청 → 데모 결과 | **FAIL / BLOCKER** | `ENABLE_DEMO_ANALYSIS=true`여도 `.env.local` API 키가 우선되어 직접 API 요청은 `422`, 스트리밍 요청은 외부 Anthropic 연결 시도 후 TLS 오류 |
| 분석 결과 → 결과 UI | BLOCKED | `scanError` 경로로 이동해 데모 결과·요리 목록 없음 |
| 결과 → 카트 → 직원 제시 | BLOCKED | 앞선 분석 경계 실패로 검증 중단 |

자동 시나리오 결과는 25개 검사 중 10개 통과였으나, 후속 실패 대부분은 첫 분석 경계 실패의 연쇄 결과다. 독립 결함 15개로 해석하면 안 된다.

### 서버 증거

```text
POST /api/analyze 400
POST /api/analyze 422
POST /api/analyze 200  # SSE 연결 자체는 열림
[TransTaste] Stream error: APIConnectionError: Connection error.
cause: UNABLE_TO_VERIFY_LEAF_SIGNATURE
```

외부 호출은 TLS 인증서 검증 단계에서 실패했다. 제공사 응답까지 도달했거나 과금됐다고 볼 증거는 없지만, 애플리케이션이 외부 호출을 시도한 사실 자체가 데모·QA 안전 경계 위반이다.

## 6. 원인 분석

`/api/analyze`와 `/api/analyze/detail`은 다음 우선순위를 사용한다.

```text
API 키 없음 + ENABLE_DEMO_ANALYSIS=true → 데모
API 키 없음 + 데모 꺼짐 → 503
API 키 있음 → 실제 AI
```

따라서 개발자의 `.env.local`에 API 키가 있으면 `ENABLE_DEMO_ANALYSIS=true`만으로는 데모를 강제할 수 없다. 기존 문서의 “명시적 데모 환경”과 자동 QA의 “유료 호출 금지”를 동시에 만족하지 못한다.

## 7. 권장 수정과 회귀 QA

### P0 — 데모 우선순위 명시

다음 중 하나를 제품 정책으로 확정해야 한다.

1. `ENABLE_DEMO_ANALYSIS=true`이면 API 키 존재 여부와 관계없이 항상 고정 데모를 반환한다.
2. 별도 서버 전용 `ANALYSIS_MODE=demo|live|disabled`를 도입하고 모드를 상호 배타적으로 만든다.

권장안은 2번이다. 이름만으로 현재 동작을 알 수 있고 QA·Preview·Production 설정 실수를 줄인다.

### P0 — 안전한 기능 QA 하네스

- 테스트 시작 전에 서버의 분석 모드가 `demo`인지 읽기 전용 상태 API로 확인한다.
- 상태가 확인되지 않으면 테스트가 분석 POST 전에 즉시 종료되어야 한다.
- 데모 시나리오는 외부 Anthropic 호스트 요청이 0건임을 네트워크 로그로 확인해야 한다.
- 이 안전장치가 생기기 전에는 분석 POST를 포함하는 기능 QA 스크립트를 저장소 명령으로 제공하지 않는다.

### 회귀 시나리오

데모 경계 수정 후 다음을 한 흐름으로 재검증한다.

1. 샘플 선택 → 비건·peanut 저장
2. `/api/analyze` → `200`, `demo: true`, 외부 AI 요청 0건
3. 결과 위험도·데모 배지·요리 3개 이상
4. 상세 API → 데모 상세
5. 주문 추가 → 수량 2개 → 직원 제시
6. 현지어 주문·AI 경고 → 확인 완료
7. 기록·캐시 생성
8. 샘플 사용 시 실제 분석 크레딧이 차감되지 않는지 확인
9. 7일 패스 관심 이벤트 속성 확인
